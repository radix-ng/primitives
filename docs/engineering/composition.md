# Composition primitives

## Shared building blocks (composition primitives in `packages/primitives/`)

These are the headless infrastructure layers that complex primitives compose:

- **`core`** — `createContext`, `useArrowNavigation`, id generators, shared types (`DataOrientation`, `AcceptableValue`, `Direction`, `BooleanInput`/`NumberInput`), `isNullish`/`isEqual`, `RdxLiveAnnouncer`, `rdxPlatform` (the single platform-detection util — `engine.{webkit,gecko,blink}` from a `-webkit-backdrop-filter` CSS probe rather than a UA match, `os.{ios,android,mac,windows,linux,apple}`, `screenReader.voiceOver`, `env.jsdom`; static and SSR-safe, and the only place the library is allowed to sniff — it replaced the four hand-rolled `isWebKit`/`isIOS`/`isFirefox` copies in scroll-lock, dismissal, and number-field), plus overlay infrastructure shared across primitives: `useTransitionStatus` (open/close transition state machine; completes on the real `animationend`/`transitionend` via the Web Animations API, with `getMaxTransitionDuration` now only feeding a safety-net timer for transitions that never settle — used by dialog, popover, collapsible, tabs, navigation-menu) and `useScrollLock` — a Base UI port (ADR 0016): a **per-`Document`** `ScrollLocker` (WeakMap, iframe-safe) with overlay-scrollbar / inset-scrollbar strategies, scroll-position save-restore, and a strategy-independent `data-rdx-scroll-locked` marker (`useAnchoredScrollLock` adds the touch near-fullscreen rule). The shared **floating-engine** infrastructure also lives here under `core/floating`: the neutral `RdxFloatingTree` + node / trigger registries + typed events (ADR 0015 §1) that dismissal and focus both read, plus `setupInternalBackdrop` (the cut-out modal backdrop). **Internal layout:** top-level files are grouped into `dom/` (DOM/browser access: `document`, `element-size`, `get-active-element`, `platform`, `use-resize-observer`, `use-scroll-lock`), `composables/` (reka-ui-style: `use-arrow-navigation`, `use-grace-area`, `use-transition-status`, `watch`), `predicates.ts` (`isNullish`, `isEqual`), plus the existing `accessor/`, `date-time/`, `positioning/`, `signal-forms/`. File names are kebab-case; export names are unchanged, and everything is re-exported from the package barrel `index.ts` (consumers never deep-import). `isEqual` is a compact structural deep-equal for primitive/array/plain-object values — the old `object-hash`-style `serialize` helper was removed. Dead/unused exports were dropped in a breaking cleanup: `injectIsClient`, `WINDOW`/`injectWindow`, `isInsideForm`, `isNumber`, `injectNgControl`, `RdxFocusInitialDirective`, `isValueEqualOrExist`, and the unused `OnMountDirective`
- **`collection`** — `RdxCollectionProvider` + `RdxCollectionItem`: collects child items in DOM order via `contentChildren`; only used by `select` currently
- **`portal`** — `RdxPortal` teleports a host element into a container (default `document.body`); `RdxPortalPresence` (structural `ng-template`) merges portal + presence — it relocates **all** template root nodes into the container with **no wrapper element**, the basis of the flattened `*rdxXxxPortal` anatomy (ADR 0010)
- **`presence`** — conditional mount/unmount with enter/leave animation support. Exit detection is Web-Animations-API-based and **subtree-aware** (ADR 0011): a closed-state `@keyframes` **or** transition on any watched root **or descendant** suspends the unmount, bounded by a duration safety net. The state machine (`presence-machine.ts`) is shared by `RdxPresenceDirective` (in place) and `RdxPortalPresence` (relocating)
- **`composite`** — Base UI-style two-layer composite navigation (ADR 0001): `CompositeList` + `CompositeListItem` register items in DOM order; `CompositeRoot` + `CompositeItem` add roving tabindex and keyboard navigation. Replaced the old `roving-focus` entry point (removed), whose behavior now lives in the root/item layer. Registration is a stable element→item **Map + tick counter** (Base UI parity), so mounting N items is roughly O(n log n) rather than the O(n²) an array-copy-per-registration would cost, and `indexOf` is an O(1) lookup over a memoized index map (verified in `apps/radix-perf-testing`). A `MutationObserver` on the items' bounding containers detects an **in-place reorder** — an `@for` with `track` reuses views and moves DOM nodes without re-registering, which would otherwise leave the index map and roving tabindex stale — and re-sorts. Two `useCompositeRoot` parity fixes: `scrollIntoViewIfNeeded` aligns the leading edge per direction (LTR resolves right-edge overflow first, RTL left) for a wider-than-container item, and the disabled-highlight re-validation is **gated on `disabledIndices` being provided** — a deliberate divergence from Base UI's controlled-index skip, since Angular's `model()` can't distinguish a controlled `highlightedIndex` from an uncontrolled one. One **Angular-specific divergence**: Base UI resolves an item's root/list through React context (the rendered tree), while Angular's element injector follows the **declaring** template — so an item projected through `<ng-content />` into a `List` that lives in a wrapper's own template can't inject it and drops out of the collection. `RdxCompositeItemOwner` (`composite/src/composite-item-owner.ts`, `@internal`) is the bridge: a primitive republishes its List's root/list contexts as signals on its Root context and provides an owner on each item part, which `RdxCompositeItem` / `RdxCompositeListItem` prefer over injection. The owner is authoritative even while `null` (no fallback to a nearer root), so the Root must stay in the projected items' declaring tree — wrappers compose it onto their host — and a primitive that later nests a second composite root has to make its owner conditional. The owner can also supply an optional `tabIndex` policy (ADR 0056): Navigation Menu retains native Tab stops while sharing arrow navigation; Composite and Tabs keep their default roving behavior. Opt-in primitives are `tabs`, `navigation-menu` and `menu` (ADR 0057). Menu publishes its Popup list per Root; SubTrigger joins the parent Root list
- **`focus-scope`** — the low-level focus trap (owner-`Document`-scoped, shadow/`composedPath`-aware) plus the focus-guards toolkit (`focus-scope/src/focus-guards.ts` — sentinel elements for focus containment; the old standalone `focus-guards` entry was removed). Composed by `floating-focus-manager` (see the floating overlay engine decision below)
- **`popper`** — floating-ui wrapper for positioned overlays
- **`dismissable-layer`** — outside-dismiss (Escape / pointer-down-outside / focus-outside) as the `RdxDismiss` capability attached to the shared floating tree (ADR 0015). The old process-global layer stack, `rdxDismissableLayerBranch`, and the `disableOutsidePointerEvents` body toggle were removed — ancestry / inside-element checks now read the neutral `RdxFloatingTree` + trigger registry in `core/floating` (focus-outside is still async, two microtasks)

## Integration notes

Complex components compose these headless building blocks — good entry points when tracing behavior:

- `core` — `createContext`, `useArrowNavigation`, id generators, shared types/utils.
- `portal` — `RdxPortal` (attribute): teleports its host element into a container (default `document.body`), reactively; non-element containers fall back to body. `RdxPortalPresence` (structural, `ng-template`): merges portal + presence — mounts its template while `present()` (from `RDX_PRESENCE_CONTEXT`) is true, relocates **all** root nodes into the container with **no wrapper element**, and waits for exit animations before unmounting (dialog backdrop + popup). Since ADR 0011 the wait is Web-Animations-API-based and **subtree-aware**: an exit `@keyframes` **or** transition on any watched root **or any descendant** suspends the unmount (bounded by a duration safety net), so the popup's own exit keeps it mounted — no positioner "decoy" keyframe. This is the ADR 0010 anatomy-flattening primitive; popover is the migrated pilot (`*rdxPopoverPortal` on the positioner). Entry depends on `presence` and `core`.
- `presence` — conditional mount/unmount with enter/leave animation support. The state machine lives in `presence/src/presence-machine.ts` (`PresenceMachine`, parameterized by `mountView`/`destroyView`); both `RdxPresenceDirective` (in place) and `RdxPortalPresence` (relocating) reuse it.
- `composite`, `focus-scope`, `popper` — ordered composite item registration / roving focus, focus trapping, positioning. Use `RdxCompositeList` when a primitive only needs DOM-order item metadata without roving focus. **Content projection (ADR 0001):** items resolve their root/list through the _declaring_ injector tree, so an item projected into a `List` declared in a wrapper's own template can't inject it. `RdxCompositeItemOwner` bridges that — the primitive republishes the List's contexts as signals on its Root context and provides an owner on each item part (`tabs-composite-item-owner.ts`, `navigation-menu-composite-item-owner.ts`, `menu-composite-item-owner.ts`). An owner wins over injection even while its signals are `null`, so the Root must stay on the wrapper's _host_, and nesting a second composite root inside such a primitive requires making the owner conditional. **Thin positioners (ADR 0012):** every `<name>-positioner.ts` **`extends RdxPopperContentWrapper`** rather than composing it via `hostDirectives` — don't re-declare the ~11 positioning inputs (they're inherited; re-declaring re-introduces the doc-vs-runtime drift bug). Use `providers: [...provideRdxPopperContentWrapper(SelfClass), provideRdxPopperContentConfig({ … })]` (the helper re-wires the `useExisting` alias + context since Angular doesn't inherit a base directive's `providers`); per-primitive defaults live **only** in the config provider. The wrapper emits the unified `--anchor-*`/`--available-*`/`--positioner-*`/`--transform-origin` vars + `data-side`/`data-align`/`data-anchor-hidden` for everyone; `legacyPopperVars('<name>')` supplies the deprecated `--radix-<name>-*` aliases for one release. **`z-index` belongs on the positioner** (the wrapper no longer copies the popup's z, so a positioner no longer requires an inner `RdxPopperContent`). Behavior subclasses (grace-area, cursor-follow, tokens) add their logic and call `super()` — use a distinct `ElementRef` field name (e.g. `containerRef`), not `elementRef`, to avoid clobbering the base's.
- `dismissable-layer` — outside-dismiss (Escape / pointer-down-outside / focus-outside) as the `RdxDismiss` capability (`RdxDismissProps`), attached to the shared floating tree (ADR 0015). **Gotcha:** the focus-outside check is **async** (defers two microtasks before deciding), so an element that takes focus _outside_ a layer and then opens it can be dismissed a tick later. Mark such elements **"inside"** so focus/pointer on them won't dismiss — via `RdxFloatingInsideElement`, or (for triggers) the shared trigger registry the root exposes as `registerTrigger`, which the floating tree reads as inside. This replaced the removed process-global layer stack + `rdxDismissableLayerBranch` / `RdxDismissableLayersContextToken.branches` and the `disableOutsidePointerEvents` body toggle (modal pointer-blocking is now a cut-out `RdxInternalBackdrop`; ADR 0016/0017). Example: a menu trigger the menubar focuses before opening a sibling popup.
- `menu` / `menubar` — Menubar is a **coordinator over `rdxMenuRoot` + the standard `rdxMenuTrigger`** (no dedicated menubar-trigger directive, mirroring Base UI). The trigger reports interactions up via `registerTriggerInteractionHandler`; the menubar owns composite focus, arrow-key nav, and hover-to-switch.
- `context-menu` — two parts only: `RdxContextMenuRoot` (composes `RdxMenuRoot`, sets `RdxPopper.anchorOverride` to a `VirtualElement` at the cursor) and `RdxContextMenuTrigger` (opens on right-click / touch long-press). All popup parts come from `RdxMenuModule`. Native pointer and keyboard `contextmenu` events focus the first tabbable control or the popup, with no initial item highlight; arrow keys enter the list. Touch uses a 500ms long-press with per-axis 10px slop and cancels on a second finger. Explicit `openAt(..., 'first')` remains available for application-defined initial item focus.
- `checkbox` — `RdxCheckboxGroupDirective` lives in the **same entry** as `RdxCheckboxRootDirective` (not a separate ng-packagr entry) because root imports the `CheckedState` type from group and group imports context from root — a cross-entry circular dep that ng-packagr rejects. `parent` input on root makes it a "select all" with Base UI's cycle (partial → all → none → partial restored) and disabled-child preservation.
