# Navigation Menu is a Base UI-style compound

`navigation-menu` was rewritten off its Radix port into the Base UI part set (Root/List/Item/Trigger/Icon/Content/Link/Portal/Backdrop/Positioner/Popup/Arrow/Viewport, `navigationMenuImports` array). A menubar `List` of triggers/links shares **one** popup, anchored to the active trigger via the `popper` primitive (`RdxPopper` on the Root, like `popover`) and mounted through `presence`/`portal`. The Root owns a `value`/`defaultValue` model (`open = value != null`) with `delay`/`closeDelay` (default 50) and a `useTransitionStatus` state machine; each `Item`'s `*rdxNavigationMenuContent` template is rendered into the shared `Viewport`, which morphs size and slides via `data-activation-direction`/`data-previous`. Top-level list arrow navigation uses `CompositeRoot`; nested Lists publish null composite contexts so their triggers join the surrounding content navigation and retain native tab order (ADR 0055). Keyboard model: composite focus moves between triggers/links, native Enter/Space clicks and the orientation opening key (ArrowDown / ArrowRight) retain trigger focus; Tab enters that trigger's content in logical order, the open panel is navigated with arrows/Home/End (handled on the nearest `Viewport`, with a `Popup` surface fallback), and open-follows-focus switches the active item while open. Triggers register as floating-tree branches (inside-elements) so focus/pointer moving to a sibling trigger doesn't dismiss. Nested menus are a `Root` inside a `Content` (detected with `inject(RdxNavigationMenuRoot, { skipSelf })`); each `Viewport` owns arrows for its content, excluding child viewports while retaining their triggers; inline children delegate Tab departure to the enclosing portaled viewport. Persistent inline stories cancel close requests through `onOpenChange` rather than ignoring an emitted null Angular model value. This removed CDK `FocusKeyManager` and `FocusableOption` from the codebase
