# Autocomplete is the combobox engine in `selectionMode: 'none'`

`autocomplete` (`@radix-ng/primitives/autocomplete`) is a text input with a filtered suggestion list. The `RdxAutocompleteRoot` doesn't reimplement the popup/list/navigation machinery: it `provideComboboxRootContext(...)` and reuses the combobox parts, but adapts the context so selection mode is `'none'` — there is no separate selected object, the **form value _is_ the input string** (`value = model<string>`). Typing, picking an item, or clearing all mutate that one string; it implements `ControlValueAccessor` for Reactive/Template forms (see `signal-forms-readiness.md`). Beyond the combobox base it adds: a `mode` input (`'list'` filter-only, `'inline'` completion-only, `'both'`) with inline-completion preview (`inlinePreview`/`displayValue`, a transient label suggestion the input shows before commit); edit-driven suppression based on `InputEvent.inputType` (`delete*` / cut / mobile Backspace suppress, insert / paste / IME commit restore); `autoHighlight` (`false` / `true` = highlight first match on input change / `'always'`) and `keepHighlight`/`highlightItemOnHover` hover-vs-keyboard split; `grid` mode for 2D row/column arrow nav; the same external `virtualized` path as combobox (navigates `items` by index, exposes `filteredItems()` for a consumer virtualizer, none shipped); pluggable `filter` (locale-aware "contains" via `useFilter` by default, a custom matcher, or `null` to disable built-in filtering) with `limit`; and `modal`/`submitOnItemClick`/`openOnInputClick` behavior flags. Compodoc gotcha note in `docs/engineering/consumer-skills.md` (`coerceAutoHighlight` is a named function, not an inline arrow + union generics) lives here for the same reason as `combobox-root.ts`.
