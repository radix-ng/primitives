# Combobox supports external list virtualization

an opt-in `virtualized` mode where the root takes the full dataset as `items` and navigates/filters by **index** over that data instead of over DOM-registered item directives (only a window is mounted). `filteredItems()` exposes the matching subset for an external virtualizer — the library ships none, consumers wire one (e.g. `@tanstack/angular-virtual`), so it is **not** a peer dependency. `onItemHighlighted` emits `{ value, index, reason }` so the consumer can `scrollToIndex` before the row mounts; each rendered item carries an `[index]`. The non-virtualized path uses a stable element→item **Map + tick** (and a stable Set per group), so registering N items avoids growing-array O(n²) copies and the DOM-order list materializes/sorts once per render batch. Filtering reads root signals once per query, stops at `limit`, and keeps an equal visible item sequence referentially stable so item-level visibility signals stay cached across queries such as `R` → `Ro` → `Row`; real-Chromium mount (50 / 500 / 2000) and sequential-typing (500) rows guard both paths. Object item values require `itemToStringLabel` for correct selection labels (the root warns in dev otherwise). Select is intentionally not virtualized (upstream Base UI keyboard-nav limitation).
