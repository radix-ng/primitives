# Primitive families

Read only the entry for the family being changed. Decisions and their status live in [the ADR index](../adr/README.md).

Decisions are recorded as ADRs in `docs/adr/` — see `docs/adr/README.md` for the status index and `docs/adr/template.md` for the header convention (fixed `Status` vocabulary: Proposed / Accepted / Rejected / Deprecated / Superseded by ADR-XXXX). The entries below summarize the load-bearing ones.

- **`hostDirectives` composition** — primitives reuse each other (e.g., AccordionItem composes CollapsibleRoot) without inheritance
- **Checkbox group co-location** — `RdxCheckboxGroupDirective` lives in the same ng-packagr entry as `RdxCheckboxRootDirective` to avoid circular cross-entry imports
- **`data-*` state only** — inline styles are never used for state; CSS custom properties are the only exception (for animation dimensions)
- **`undefined` removes attributes** — `host` bindings use `undefined` (not `null` or `false`) to remove attributes
- **`defaultValue` via `effect()`** — uncontrolled initialization is done in `constructor()` with an `effect()`
- **Dialog is a declarative compound** — `dialog` was rewritten off `cdk/dialog` into a Base UI-style compound (Root/Trigger/Portal/Backdrop/Popup/Title/Description/Close, plus Viewport and a detached-trigger handle) built on the shared floating engine (`RdxDismiss` dismissal + `RdxFloatingFocusManager` focus) plus `presence` + `portal`. It mirrors `popover` (the reference for this pattern)
- **Alert Dialog is a thin layer over Dialog** — every `alert-dialog` part is a thin `hostDirectives` wrapper around the matching dialog part (its own `rdxAlertDialog*` selector), so the dialog primitive stays headless and knows nothing about its consumers. Alert semantics come from an injected **dialog variant** (`RDX_DIALOG_VARIANT` / `provideRdxDialogVariant`), a small behavioral profile with three independent flags — `role`, `forceModal`, `forcePointerDismissalDisabled` — that the dialog root folds into its effective `modal` / `disablePointerDismissal` / popup `role`. Keeping the flags independent (rather than deriving dismissal from role) lets future variants like Drawer reuse the same hook. Alert dialogs set all three: `role="alertdialog"`, always modal, outside-press/focus-out dismissal off (Escape still closes). This removed the last `cdk/overlay`, `cdk/portal`, and `CdkTrapFocus` usage from the codebase. Same composition pattern as `context-menu` over `menu`
- **Navigation Menu is a Base UI-style compound** — `navigation-menu` was rewritten off its Radix port into the Base UI part set (Root/List/Item/Trigger/Icon/Content/Link/Portal/Backdrop/Positioner/Popup/Arrow/Viewport, `navigationMenuImports` array). A menubar `List` of triggers/links shares **one** popup, anchored to the active trigger via the `popper` primitive (`RdxPopper` on the Root, like `popover`) and mounted through `presence`/`portal`. The Root owns a `value`/`defaultValue` model (`open = value != null`) with `delay`/`closeDelay` (default 50) and a `useTransitionStatus` state machine; each `Item`'s `*rdxNavigationMenuContent` template is rendered into the shared `Viewport`, which morphs size and slides via `data-activation-direction`/`data-previous`. Top-level list arrow navigation uses `CompositeRoot`; nested Lists publish null composite contexts so their triggers join the surrounding content navigation and retain native tab order (ADR 0055). Keyboard model: composite focus moves between triggers/links, native Enter/Space clicks and the orientation opening key (ArrowDown / ArrowRight) retain trigger focus; Tab enters that trigger's content in logical order, the open panel is navigated with arrows/Home/End (handled on the nearest `Viewport`, with a `Popup` surface fallback), and open-follows-focus switches the active item while open. Triggers register as floating-tree branches (inside-elements) so focus/pointer moving to a sibling trigger doesn't dismiss. Nested menus are a `Root` inside a `Content` (detected with `inject(RdxNavigationMenuRoot, { skipSelf })`); each `Viewport` owns arrows for its content, excluding child viewports while retaining their triggers; inline children delegate Tab departure to the enclosing portaled viewport. Persistent inline stories cancel close requests through `onOpenChange` rather than ignoring an emitted null Angular model value. This removed CDK `FocusKeyManager` and `FocusableOption` from the codebase
- **Menu projection ownership (ADR 0057)** — Root owns floating node registration so projected child Roots inherit logical ancestry outside a Popup declaring view. Each Root publishes its Popup CompositeList and isRestoringFocus callback. Item parts use the existing Composite owner bridge; SubTrigger uses its parent Root. Sibling discovery reads registered instances rather than requiring selector attributes on hostDirectives wrappers. Root must stay in the projected parts' declaring tree. Popup disposal clears published references.
- **Menu submenus own their hover-close via a safe polygon** — a submenu opened **by hover** (not keyboard/click) closes _itself_ rather than being closed by a sibling stealing it. While open it attaches a single `document` `mousemove` handler that keeps it open as long as the pointer stays inside a triangular safe zone between the pointer's exit point and the popup — a faithful port of Floating UI's `safePolygon` (velocity gating, trough, per-side geometry) in `menu/src/menu-safe-polygon.ts` — plus a **pointer-events tunnel** that makes siblings inert mid-traverse (`pointer-events:none` on the parent popup, `auto` on trigger + popup), so a diagonal cut across a sibling subtrigger can't switch submenus on the way. The placed **physical** side is read **live** via the menu root context (`popupPhysicalSide`, backed by the positioner's `physicalPlacedSide`) — **not** the popup's `data-side`, which since the popper logical-side echo can be `inline-start`/`inline-end` and would skip the physical-only geometry switch (a logical-side submenu would then mis-close while the pointer moves toward it). Floating UI resolves the side async and may flip it, so the getter stays live. Nested levels are tracked by a small module-level open-submenu registry instead of Floating UI's tree. The menu root context surfaces the popup element and its physical side (`popupElement`/`popupPhysicalSide`, `registerPopup`) for the geometry. This is deliberately **not** the core `useGraceArea` composable (convex hull, `pointerleave`-driven, no tunnel): the submenu needs the richer algorithm and the sibling-blocking tunnel to match Base UI. Mouse-only and browser-only; behavior change vs. the old model — hovering a sibling now closes the open submenu. Each open submenu arms its own listener, so a deep open chain runs one handler per level (acceptable, mirrors Floating UI; a single coordinating listener is the fix if it ever profiles hot). A pending hover-**open** on a submenu trigger is also cancelled from a backup `pointerout` handler (ignoring internal crossings via `relatedTarget`), because Chrome can drop the non-bubbling `pointerleave` during a fast pointer sweep and otherwise open a stale submenu for a trigger the pointer has already left
- **Collapsible/Accordion panel lifecycle follows Base UI** — `collapsible` was realigned so the `Panel` **unmounts when closed by default** and a _mounted_ panel is kept via `hidden` rather than the old presence directive. The two-directive presence pattern was removed: `RdxCollapsiblePanelPresenceDirective` and `RdxAccordionContentPresenceDirective` are **deleted** (BREAKING); opt back into staying-mounted with the panel/root `keepMounted` input, and use `hiddenUntilFound` (panel `id` + `beforematch`) for find-in-page reveal. `onOpenChange` is now **cancelable** and emits `{ open, eventDetails }` instead of a boolean (BREAKING). Disabled triggers stay focusable via `aria-disabled` instead of native `disabled`. AccordionItem still composes CollapsibleRoot via `hostDirectives`.
- **Accordion was aligned to the Base UI part set** (BREAKING) — `data-state` is replaced by Base UI's boolean `data-open` (item/header/panel) and `data-panel-open` (trigger); the content part was renamed **`RdxAccordionContentDirective` → `RdxAccordionPanelDirective`** (selector `[rdxAccordionContent]` → `[rdxAccordionPanel]`) and its CSS size vars renamed `--radix-accordion-content-*` → **`--accordion-panel-height` / `--accordion-panel-width`**. `onValueChange` now emits `{ value, eventDetails }` (cancelable, reasons `'trigger-press' | 'none'`) and item `onOpenChange` emits `{ open, eventDetails }`. Root gained `hiddenUntilFound`; the legacy `type`, `collapsible`, and `id` inputs were **removed** (single accordions are always collapsible — use `multiple`), along with the dead item `dataState`/`RdxAccordionItemState` and the trigger's `data-rdx-collection-item` marker (old roving-focus leftover). Data attributes now mirror the Base UI contract exactly: Root `data-orientation`/`data-disabled`; Item/Header `data-open`/`data-disabled`/`data-index`; Trigger `data-panel-open`/`data-disabled`; Panel `data-open`/`data-orientation`/`data-disabled`/`data-index`/`data-starting-style`/`data-ending-style` (the composed collapsible's `data-closed` is suppressed — Base UI's panel has none). Closed panels now use plain `hidden=""` by default (was `hidden="until-found"`); opt into find-in-page with `hiddenUntilFound`. One intentional divergence remains: our `value` is scalar in single mode (Base UI always uses an array).
- **Checkbox follows the Base UI state API** — `data-checked`/`data-unchecked`/`data-indeterminate` replace `data-state` (BREAKING). Added `defaultChecked`, a `readOnly` alias, `uncheckedValue`, and `keepMounted`; `rdxCheckboxIndicatorPresence` was **removed** in favor of the indicator's `keepMounted` input (BREAKING). Disabled checkbox buttons stay focusable via `aria-disabled` instead of native `disabled`. (Group co-location is unchanged — see below.)
- **Tabs follow the Base UI part set** — `tabs` was realigned to `Root`/`List`/`Tab`/`Panel`/`Indicator` (newer no-suffix class names). Activation moved to the `List` (`activateOnFocus`, default **manual**) instead of the root; `data-active`/`data-hidden`/`data-activation-direction`/`data-starting-style`/`data-ending-style` replace `data-state`. `Panel` stays mounted and toggles `hidden` by default; `*rdxTabsPanelPresence` opts into real unmount with exit animations (Tabs keeps this two-directive presence pattern; Collapsible/Accordion dropped theirs — see the Collapsible note above). `Indicator` exposes the active tab geometry as `--active-tab-*` CSS variables.
- **Toggle is one part, standalone or grouped (Base UI)** — `toggle`/`toggle-group` were realigned so a single `RdxToggle` works on its own **or** as a `[rdxToggleGroup]` item (pressed state derived from the group's array `value`, joining its composite focus) — there is no separate group-item directive. `data-pressed` replaces `data-state`. `RdxToggleGroup` takes an **array** `value` with `multiple`/`loopFocus` (shared logic in `toggle-group-base.ts`); `RdxToggleGroupWithoutFocus` is the focus-management-less variant for toolbars.
- **Toolbar follows the Base UI part set** — `toolbar` was rewritten to `Root`/`Button`/`Link`/`Input`/`Group`/`Separator` over `CompositeRoot`, with root/group `disabled` cascading through context and `focusableWhenDisabled` keeping disabled items reachable. Toggle groups compose via `rdxToggleGroupWithoutFocus` + `rdxToggle`. `RdxToolbarInput` is a **composite input**: a constructor-registered `keydown` listener keeps arrow keys for the text caret and only yields to composite navigation when the caret is at the matching edge.
- **Switch follows the Base UI part set** — `switch` was realigned to `Root`/`Thumb`/`Input` (no-suffix classes, `createContext`). `data-checked`/`data-unchecked` replace `data-state`; added `data-disabled`/`data-readonly`/`data-required`. The root gained Base UI props `readOnly` (focusable but not toggleable), `name` and `value` (submitted via the hidden `[rdxSwitchInput]` checkbox), keeping the existing `RdxControlValueAccessor` host-directive for Reactive Forms. This also advanced `signal-forms-readiness.md` (adds `readonly`/`name`) and dropped CDK `_IdGenerator` for the `core` generator (prep #6). The `invalid`/`errors`/`touched`/`dirty` batch is still deferred to the shared Signal Forms pattern.
- **Slider is a directive-based Base UI compound** — `slider` was rewritten from components to the Base UI part set (`Root`/`Control`/`Track`/`Indicator`/`Thumb`/`ThumbInput`/`Value`), deleting the duplicated horizontal/vertical components and the orientation-context service — **one** directive set drives both orientations off the `orientation` signal. The `Root` (composing `RdxControlValueAccessor`) owns value/state/thumb-registration; the `Control` handles pointer press/drag and maps position→value; each `Thumb` wraps a visually-hidden native `input[type=range]` (`ThumbInput`) that drives keyboard, a11y and form submission. Single value is a **number**, range is a **number[]** (`range = Array.isArray(value)`); one `Thumb` per value, with `thumbCollisionBehavior` (push/swap/none), `minStepsBetweenValues`, `largeStep`, and `Intl.NumberFormat` value formatting. State is exposed via `data-orientation`/`data-disabled`/`data-dragging` (plus `data-index` per thumb). This resolved the slider blocker in `signal-forms-readiness.md` — `modelValue` was renamed to `value` (the `FormValueControl` required signal), `name`/`form` added — and switched id generation from CDK `_IdGenerator` to the `core` generator (prep #6).
- **Form is the top of the forms layer cake (Base UI `Form`)** — `form` (`form[rdxFormRoot]`, its own secondary entry `@radix-ng/primitives/form`) rides the native `<form>`: maps server/external `errors` onto fields by `name` (clearing on user edit, emitting `onClearErrors`), intercepts submit (`onFormSubmit` with `FormData`-serialized values, focus the first invalid field), resets field interaction state on native reset, and exposes aggregate `data-invalid`/`data-dirty`/`data-touched`/`data-submitting`. It owns no values or validation and never `stopPropagation`s, so Reactive Forms' `(ngSubmit)` still fires alongside. **Dependency direction is `field → form`** (Field optionally injects the Form context and registers through structural `() =>` accessors; `form` imports nothing from `field`) — the same acyclic cross-entry constraint as the checkbox/checkbox-group co-location, solved here by keeping the registration interface Form-side. Field has a `name` input, external-error merge, edit-forwarding, `RdxFieldError.messages()`, and an `RdxFieldState` provider seam. The explicit same-host `rdxNgControlField` adapter feeds Reactive/template-driven `NgControl` state into that seam and may infer the field name; the explicit root name wins. `rdxSignalField` uses the same seam, while `rdxSignalForm` uses Form's parallel `RdxFormState` seam. Field/Form still run no validation. No new runtime peer — the `field → form` edge remains internal and acyclic.
- **Form-control + display-primitive alignment pass** — a later sweep brought the rest of the families to the Base UI contract (mostly BREAKING where `data-state`/extra attributes were involved):
  - **Radio** — `data-checked`/`data-unchecked` (no `data-state`); ArrowUp/Left also _check_ (selection-follows-focus), item exposes `data-composite-item-active`; dead no-op keydown handler removed.
  - **Switch** — the hidden `[rdxSwitchInput]` no longer carries `data-checked`/`data-unchecked` (Base UI's hidden input has none; state lives on root/thumb).
  - **Slider** — removed `data-index` from `ThumbInput` (it's on `Thumb`); pointer-reason typed `'track-press' | 'drag'`.
  - **Toggle** — removed the unused, non-Base-UI `RdxToggleVisuallyHiddenInputDirective` (BREAKING export removal); the item now passes the computed `nextPressed` boolean to the group (`toggle(value, nextPressed, …)`, single source of truth); non-native hosts emulate native-button keys (Enter on keydown, Space on keyup).
  - **Checkbox** — root context is an explicit interface; `toggle()` marks the form control touched (standalone forms bug); dropped a redundant disabled alias.
  - **Label / Field / Form** — SSR-stable ids via `injectId` (replaced module counters across field root/control/label/description/error and label); explicit context interfaces (Field + Form, replacing `ReturnType<typeof>`); Field's `aria-required`/`aria-disabled` gated to non-native controls only (native attrs convey it natively); Field control gained `data-dirty`/`data-touched`; `onFormSubmit` now carries `reason: 'none'`. The cross-control validity-attr batch (`invalid/errors/touched/dirty` + `touch` output) stays the tracked Signal Forms collision #4 (copy the `input` pilot), not an ad-hoc per-primitive fix.
  - **Progress** — removed `data-state` from all five parts (boolean `data-complete`/`data-progressing`/`data-indeterminate` remain); explicit context interface; SSR-stable ids; indeterminate keeps `aria-valuemin/max` and announces `aria-valuetext="indeterminate progress"`; the value part is `aria-hidden` (no `aria-describedby` double-announce); `aria-labelledby` is register-on-mount so it never dangles.
  - **Avatar** — context migrated from the legacy `InjectionToken`/`provideToken` to `createContext`; removed forced `role="img"` on the `<img>`; added `crossOrigin`/`srcSet`/`sizes` + the `image.complete` cached fast-path; `onLoadingStatusChange` no longer fires the initial `idle`. (Deferred: image enter/leave `data-starting/ending-style` — a transition-status feature on a non-mounting `<img>`.)
  - **Scroll Area** — thumb gained `data-scrolling`; SSR-stable `rootId` via `injectId`; added the `apps/visual-regression` behavior spec (overflow metrics, focusable viewport, thumb tracking).
  - **Separator** — emits `aria-orientation` for **both** orientations (Base UI + the repo's own menu/combobox separators), not just vertical.
  - **Aspect Ratio** — switched from the `AfterViewInit` + `Renderer2` child-mutation padding-bottom hack to the native CSS `aspect-ratio` property (BREAKING: children fill the box themselves, e.g. `class="size-full object-cover"`).
  - **Toolbar** — `rdxToolbarInput` conveys disabled via `aria-disabled` only (never native `disabled`; roving removal via composite `disabledIndices`) and blocks pointer interaction while disabled.
  - **Number Field** — read-only now natively disables the stepper buttons (Base UI parity) and the invalid `aria-readonly` on `role="button"` was removed (`data-readonly` added); fixed the stories' duplicate-id label association; added the `apps/visual-regression` behavior spec (stepper click + press-and-hold). (Deferred: `onValueCommitted` `eventDetails` parity; the Field validity batch.)
- **Combobox supports external list virtualization** — an opt-in `virtualized` mode where the root takes the full dataset as `items` and navigates/filters by **index** over that data instead of over DOM-registered item directives (only a window is mounted). `filteredItems()` exposes the matching subset for an external virtualizer — the library ships none, consumers wire one (e.g. `@tanstack/angular-virtual`), so it is **not** a peer dependency. `onItemHighlighted` emits `{ value, index, reason }` so the consumer can `scrollToIndex` before the row mounts; each rendered item carries an `[index]`. The non-virtualized path uses a stable element→item **Map + tick** (and a stable Set per group), so registering N items avoids growing-array O(n²) copies and the DOM-order list materializes/sorts once per render batch. Filtering reads root signals once per query, stops at `limit`, and keeps an equal visible item sequence referentially stable so item-level visibility signals stay cached across queries such as `R` → `Ro` → `Row`; real-Chromium mount (50 / 500 / 2000) and sequential-typing (500) rows guard both paths. Object item values require `itemToStringLabel` for correct selection labels (the root warns in dev otherwise). Select is intentionally not virtualized (upstream Base UI keyboard-nav limitation).
- **Autocomplete is the combobox engine in `selectionMode: 'none'`** — `autocomplete` (`@radix-ng/primitives/autocomplete`) is a text input with a filtered suggestion list. The `RdxAutocompleteRoot` doesn't reimplement the popup/list/navigation machinery: it `provideComboboxRootContext(...)` and reuses the combobox parts, but adapts the context so selection mode is `'none'` — there is no separate selected object, the **form value _is_ the input string** (`value = model<string>`). Typing, picking an item, or clearing all mutate that one string; it implements `ControlValueAccessor` for Reactive/Template forms (see `signal-forms-readiness.md`). Beyond the combobox base it adds: a `mode` input (`'list'` filter-only, `'inline'` completion-only, `'both'`) with inline-completion preview (`inlinePreview`/`displayValue`, a transient label suggestion the input shows before commit); edit-driven suppression based on `InputEvent.inputType` (`delete*` / cut / mobile Backspace suppress, insert / paste / IME commit restore); `autoHighlight` (`false` / `true` = highlight first match on input change / `'always'`) and `keepHighlight`/`highlightItemOnHover` hover-vs-keyboard split; `grid` mode for 2D row/column arrow nav; the same external `virtualized` path as combobox (navigates `items` by index, exposes `filteredItems()` for a consumer virtualizer, none shipped); pluggable `filter` (locale-aware "contains" via `useFilter` by default, a custom matcher, or `null` to disable built-in filtering) with `limit`; and `modal`/`submitOnItemClick`/`openOnInputClick` behavior flags. Compodoc gotcha note in CLAUDE.md (`coerceAutoHighlight` is a named function, not an inline arrow + union generics) lives here for the same reason as `combobox-root.ts`.
- **Flattened overlay anatomy (ADR 0010)** — popup primitives match Base UI's two-element `Positioner → Popup` anatomy: a single **structural** `*rdxXxxPortal` directive (on an `ng-template`, composing `RdxPortalPresence`) merges the old portal + presence wrapper elements into one and relocates its template root(s) into the container with no extra wrapper. A dev-mode misuse guard throws if `rdxXxxPortal` is put on a non-`ng-template`. Migrated: popover (pilot), tooltip, preview-card, dialog/drawer/alert-dialog, combobox/autocomplete, navigation-menu, menu, select; the shared engine is `RdxPortalPresence` (`portal`) + `PresenceMachine` (`presence`). Multi-root templates (dialog backdrop + popup) are supported — the machine watches every `HTMLElement` root.
- **Thin positioners (ADR 0012)** — every `<name>-positioner.ts` **`extends RdxPopperContentWrapper`** rather than composing it via `hostDirectives`. The ~11 positioning inputs, the `placed` output, and the host bindings are **inherited** (declared once on the wrapper); per-primitive defaults live only in `provideRdxPopperContentConfig(...)`; `provideRdxPopperContentWrapper(SelfClass)` re-wires the DI alias + context (Angular doesn't inherit a base directive's `providers`). The wrapper emits the unified Base UI CSS vars (`--anchor-*`, `--available-*`, `--positioner-*`, `--transform-origin`) and `data-side`/`data-align`/`data-anchor-hidden` once for everyone; `legacyPopperVars('<name>')` keeps the deprecated `--radix-<name>-*` aliases for one release. **z-index belongs on the positioner** (the wrapper no longer copies the popup's z-index, so a positioner no longer requires an inner `RdxPopperContent`). This cut positioner code ~1045→409 lines and removed a docs-vs-runtime default-drift bug (combobox/autocomplete/select were publishing wrong defaults). The docs pipeline resolves the inherited config defaults in `api-contract.mjs` + the Storybook compodoc plugin.
- **Popper logical sides (Base UI `useAnchorPositioning` parity)** — the positioner `side` input accepts the logical `inline-start` / `inline-end` alongside physical `top`/`right`/`bottom`/`left`; they resolve to `left`/`right` by text direction (a `dir` input on the wrapper falling back to the enclosing direction provider). The public placement state **echoes the kind requested**: `data-side` / `placedSide()` and the `OffsetFunction`'s `side` stay logical when a logical side was passed — even after a collision flip re-sides the popup — and stay physical for a physical request, so a `[data-side="inline-start"]` style rule is direction-agnostic and per-primitive popups/arrows inherit the echo through context with no change. The arrow, transform-origin, and menu safe-polygon geometry read a **separate internal `physicalPlacedSide`**, because their `OPPOSITE_SIDE` / geometry maps need the real physical side a logical `data-side` would break (any downstream consumer that reads `data-side` as a physical value must use this channel instead). This is the last item of the popper audit; `disableAnchorTracking` and the submenu POPUP-vs-DROPDOWN split remain deferred.
- **Floating overlay engine (ADR 0015–0017, 0023)** — dismissal, focus, and scroll-lock were rewritten to Base UI's model over a **shared neutral floating tree** (`core/floating`: `RdxFloatingTree` + node / trigger registries + typed events), replacing the CDK overlay and the old process-global dismissable-layer stack. **Dismissal** is the `RdxDismiss` capability (ADR 0015) reading that tree; **focus** is `RdxFloatingFocusManager` (ADR 0017), which composes `focus-scope` and owns the coordinated policy set — trap, aria-hidden isolation, the `markOthers` marker that dismissal's outside-press guard reads, and initial / return / restore focus + close-on-focus-out; modal pointer-blocking is a cut-out `RdxInternalBackdrop` (`setupInternalBackdrop`) instead of a body `pointer-events` toggle; **scroll-lock** is the ADR 0016 port. The focus manager is Accepted and in production for dialog, popover, menu, and select (plus context-menu / menubar via menu); Combobox / Autocomplete adoption, the modal Popover backdrop, the full portal-focus bridge, and the Phase-5 verification matrix are the de-scoped remainder tracked in **ADR 0023**.
- **Scroll Area is a Base UI compound ported from `mui/base-ui`** — `scroll-area` is the Base UI part set (`Root`/`Viewport`/`Content`/`Scrollbar`/`Thumb`/`Corner`, no-suffix classes, `createContext`). It keeps the browser's **native** scrolling (momentum, keyboard, a11y), hides the platform scrollbar via a one-time injected stylesheet keyed on `[rdxScrollAreaViewport]`, and renders a custom thumb. The `Viewport` owns the measurement pass (`computeThumbPosition`): driven by `afterNextRender` + a `ResizeObserver` on the viewport and on the `Content`, plus an `effect` re-running on hidden-state/direction/threshold changes, it sizes/positions each thumb (`translate3d`), publishes overflow state as `data-scrolling`/`data-hovering`/`data-has-overflow-x/y`/`data-overflow-*-start/end`, and sets edge-distance CSS variables (`--scroll-area-overflow-*`, used by the gradient-fade example) plus `--scroll-area-corner-*` / `--scroll-area-thumb-*`. The `Root` holds the shared state and the imperative drag/wheel/track-click handlers; element refs are shared through context as React-style `{ current }` holders (child parts register in their constructor/`effect`). Scrolls are attributed to the user (vs. programmatic, e.g. `scrollTo`) by a preceding interaction event — except in **touch modality**, where every scroll counts as user-driven: WebKit consumes a touch that catches an in-flight momentum / rubber-band scroll without dispatching any DOM events, so on iOS `data-scrolling` (scrollbar visibility) can't be gated on interaction events. Two ports-to-Angular adaptations: a directive can't unmount its own host, so a `Scrollbar`/`Corner` that Base UI would unmount instead hides via `display: none` (`keepMounted` keeps it present); `RdxTabsIndicator` geometry was made content-relative (adds the list's `scrollLeft`/`scrollTop`) so the active-tab indicator tracks correctly when a `Tabs.List` is rendered as a `ScrollArea.Viewport` (the "combining with Tabs" example stacks both directives on one element).

**Menu multiple triggers and moving viewports (ADR 0059):** Menu Root keeps registrations by native element, exposes `[(triggerId)]`/`defaultTriggerId` and a typed `payload()` through `createRdxMenuHandle<Payload>()`. Explicit handles remain authoritative while unattached; native button tabindex is supplied only when unauthored. `core/floating/popup-handle-registry.ts` shares root/trigger replacement lifetimes with Popover and Dialog. `core/floating/use-popup-viewport.ts` shares inert visual snapshots and transition cleanup with Popover; use one direct live content wrapper. Menu publishes measured size to Popup/Positioner. Programmatic focus return prefers the pre-open control, with a connected owner-reference fallback supplied to the shared Focus Scope.
