# OTP Field

#### A headless one-time-code control built from one native input per character.

<Canvas sourceState="hidden" of={Stories.Default} />

## Features

- ✅ Renders independently focusable native inputs for each character and a hidden form control for submission and validation.
- ✅ Supports controlled and uncontrolled values, normalization, numeric or text validation, masking, and one-time-code autofill.
- ✅ Distributes typing and pasted text across slots, with keyboard navigation between characters.
- ✅ Integrates with Reactive Forms, `ngModel`, and Angular Signal Forms.
- ✅ Exposes completion, invalid-input, and cancellable value-change events.
- ✅ Supports visual grouping and separators without imposing styles or layout.

## Import

```ts
import { RdxOtpFieldInput, RdxOtpFieldModule, RdxOtpFieldRoot, RdxOtpFieldSeparator } from '@radix-ng/primitives/otp-field';
```

## Anatomy

Apply `rdxOtpFieldRoot` to a wrapper, then add one `rdxOtpFieldInput` native input for each character. A separator is optional and purely presentational.

```html
<div rdxOtpFieldRoot [length]="6" name="verificationCode" [autoComplete]="'one-time-code'">
  <input rdxOtpFieldInput />
  <input rdxOtpFieldInput aria-label="Character 2 of 6" />
  <input rdxOtpFieldInput aria-label="Character 3 of 6" />
  <input rdxOtpFieldInput aria-label="Character 4 of 6" />
  <input rdxOtpFieldInput aria-label="Character 5 of 6" />
  <input rdxOtpFieldInput aria-label="Character 6 of 6" />
</div>
```

The root's `length` is required and should match the number of slot inputs. Slot indices follow DOM order, including inputs nested in layout wrappers. The first slot receives the root `id`; later slots receive numbered ids.

## Events

`onValueChange` emits the proposed string with event details. Call `eventDetails.cancel()` from the handler to prevent an update. Its reason is one of `input-change`, `input-clear`, `input-paste`, or `keyboard`.

`valueComplete` is emitted after a value reaches the configured length, with a reason of `input-change` or `input-paste`. `valueInvalid` reports attempted text that did not pass validation. With `autoSubmit`, a complete code is applied before the associated form is submitted.

## API Reference

### Root

`RdxOtpFieldRoot` owns the value, validation and slot coordination.

<ArgTypes of={RdxOtpFieldRoot} />

**Inputs:** `value`, `defaultValue`, required positive integer `length`, `validationType`, `normalizeValue`, `mask`, `autoComplete`, `autoSubmit`, `inputMode`, `name`, `form`, `disabled`, `readonly`, `required`, and `id`.

**Outputs:** `onValueChange`, `valueComplete`, and `valueInvalid`.

**State attributes:** `data-disabled`, `data-readonly`, `data-required`, `data-valid`, `data-invalid`, `data-dirty`, `data-touched`, `data-complete`, `data-filled`, and `data-focused`. Root `data-filled` is present when any character has been entered.

## Data attributes

| Attribute | Parts | Values |
| --- | --- | --- |
| `data-disabled` | Root, Input | Present when interaction is disabled. |
| `data-readonly` | Root, Input | Present when edits are disallowed. |
| `data-required` | Root, Input | Present when a complete value is required. |
| `data-valid` | Root, Input | Present when the form state is valid. |
| `data-invalid` | Root, Input | Present when the form state is invalid. |
| `data-dirty` | Root, Input | Present after the value changes. |
| `data-touched` | Root, Input | Present after focus leaves the field. |
| `data-complete` | Root, Input | Present when the value has one character per slot. |
| `data-filled` | Root, Input | Root: any character; Input: that slot has a character. |
| `data-focused` | Root, Input | Present while any slot has focus. |

### Input

`RdxOtpFieldInput` is a native text input associated with one character slot. Slots expose their DOM-order `index`, current `value`, and `filled` state.

<ArgTypes of={RdxOtpFieldInput} />

**State attributes:** `data-disabled`, `data-readonly`, `data-required`, `data-valid`, `data-invalid`, `data-dirty`, `data-touched`, `data-complete`, `data-filled`, and `data-focused`. On a slot, `data-filled` reflects that character; `data-focused` indicates that focus is within the OTP field. Use `:focus` to style the currently focused slot.

### Separator

`RdxOtpFieldSeparator` marks a visual break between slot groups and has no inputs.

<ArgTypes of={RdxOtpFieldSeparator} />

## Keyboard interactions

| Key | Description |
| --- | --- |
| Character key | Accept a valid character and advance focus to the next slot. |
| `Backspace` | Clear the current character; when empty, move to and clear the previous slot. |
| `Delete` | Clear the current character. |
| `ArrowLeft` / `ArrowRight` | Move focus to the previous or next slot. |
| `Home` / `End` | Move focus to the first or last slot. |

Pasting a multi-character value distributes accepted characters across the slots and reports rejected characters through `valueInvalid`. Invalid single-character input is rejected without changing the value.
