# Toast

#### A succinct, low-priority message that appears temporarily, stacks, and can be swiped away.

<Canvas sourceState="hidden" of={Stories.Default} />

## Features

- ✅ Imperative API — push toasts from anywhere with `add` / `update` / `close` / `promise`.
- ✅ Headless and unstyled — state is exposed through `data-*` attributes and CSS variables.
- ✅ Stacking with a hover/focus expand, driven by measured heights (`--toast-offset-y`).
- ✅ Swipe-to-dismiss with axis locking, resistance, and cancellation.
- ✅ Auto-dismiss timers that pause during hover, keyboard focus, swipe, or while the window is inactive.
- ✅ Promise toasts with `loading` / `success` / `error` copy.
- ✅ A polite notifications region, with assertive announcements for high-priority toasts.

## Import

```ts
import {
    provideRdxToastManager,
    RdxToastClose,
    RdxToastContent,
    RdxToastDescription,
    RdxToastManager,
    RdxToastPortal,
    RdxToastRoot,
    RdxToastTitle,
    RdxToastViewport
} from '@radix-ng/primitives/toast';
```

Use `provideRdxToastManager()` in the component's providers or `[rdxToastProvider]` on a wrapper.
Inject `RdxToastManager` from that scope to push notifications into the same queue.

## Anatomy

Provide the manager once, render the viewport, and iterate the queue. Each item from
`manager.toasts()` is bound to a `rdxToastRoot`.

```html
<div>
    <div rdxToastPortal>
        <div rdxToastViewport>
            @for (toast of manager.toasts(); track toast.id) {
                <div class="data-limited:hidden" rdxToastRoot [toast]="toast">
                    <div rdxToastContent>
                        <p rdxToastTitle>{{ toast.title }}</p>
                        <p rdxToastDescription>{{ toast.description }}</p>
                        <button rdxToastClose>Dismiss</button>
                    </div>
                </div>
            }
        </div>
    </div>
</div>
```

```ts
const manager = inject(RdxToastManager);
manager.add({ title: 'Saved', description: 'Your changes are live.' });
```

Wrap an anchored toast in `rdxToastPositioner` and put `rdxToastArrow` inside the Root to show a
decorative arrow. Import both directives from `@radix-ng/primitives/toast`.

```html
<div rdxToastPositioner [anchor]="toast.positionerProps.anchor">
    <div rdxToastRoot [toast]="toast">
        <span rdxToastArrow></span>
        <div rdxToastContent>
            <p rdxToastTitle></p>
        </div>
    </div>
</div>
```

### Default

Push a single toast; it auto-dismisses after the timeout.

<Canvas of={Stories.Default} />

### Stacking

Add several toasts to see the collapsed stack, then hover or focus it to expand. The default limit
is three visible notifications. The oldest excess notifications stay in the queue with `data-limited`
and `inert`. Hide them in CSS with `data-limited:hidden` and let the manager promote them when a
visible notification starts closing.

<Canvas of={Stories.Stacking} />

### Swipe to dismiss

Drag in an allowed `swipeDirection` and release after travelling more than 40 CSS pixels.
When both axes are allowed, the first displacement locks the axis. Reversing an armed swipe can
cancel it. A short release or `pointercancel` returns the toast to its resting position.

Buttons, links, inputs, textareas, and elements with `role="button"` keep their native interactions.
Use `data-base-ui-swipe-ignore` on other regions that should opt out. Angular also supports
`data-swipe-ignore` and `data-toast-swipe-ignore`.

<Canvas of={Stories.SwipeToDismiss} />

### Promise

Drive one toast through `loading`, then `success` or `error`. The timer starts when the promise
settles and uses the result's `timeout` or the provider default. A result with `timeout: 0` stays
until dismissed.

Each settlement updates the active toast with the request's `id`. When requests share an ID,
the last settlement supplies the visible result. Use distinct IDs for independent notifications.

<Canvas of={Stories.Promise} />

### Types

Branch on a free-form `type` to render an icon, and raise `priority` to `high` for assertive errors.

### Custom position

Placement is the consumer's CSS — here the viewport is anchored top-center and the stack grows down.

### Undo action

`rdxToastAction` adds an in-toast action button; this one undoes the change and dismisses the toast.

### Deduplicated

Pass a fixed `id` to upsert a single toast in place instead of stacking duplicates.
Reusing the ID during exit replaces the toast and discards that exit's `onRemove`. The
replacement has its own `onClose` and `onRemove` callbacks.

## Keyboard and announcements

Press `F6` to focus the notifications region. `Tab` visits the notifications and their controls.
Press `F6` again or `Shift+Tab` from the region to return to the previous control. `Escape` dismisses
the notification that contains focus. When that notification closes, focus moves to another
available notification or returns to the previous control.

Supply a `rdxToastTitle` or an `aria-label` to name each notification dialog. A `rdxToastDescription`
supplies its description. The viewport announces normal messages politely and announces messages
with `priority: 'high'` assertively.

## Enter and exit motion

Use `[data-starting-style]` on `rdxToastRoot` for the initial state of an enter transition. Apply the
exit transition or keyframes to `rdxToastRoot[data-ending-style]`. The queue waits for finite CSS
motion on the Root before removing it. A toast with zero-duration motion leaves after its ending
state renders. Animations on child parts run independently of removal.

**Migration.** Replace `[data-state="closed"]` on Root with `[data-ending-style]`. For enter
keyframes, use a base animation class on Root with an ending-style override. For collapsed stack
styling, use `[data-behind]` on Content in place of `[data-front]` on Root.

## Data attributes

| Attribute              | Part                                     | Present when                                           |
| ---------------------- | ---------------------------------------- | ------------------------------------------------------ |
| `data-starting-style`  | Root                                     | the notification is applying its initial enter style   |
| `data-ending-style`    | Root                                     | dismissal has begun                                    |
| `data-limited`         | Root                                     | the notification is beyond the visible limit           |
| `data-expanded`        | Viewport, Root, Content                  | the viewport is hovered or has keyboard focus          |
| `data-behind`          | Content                                  | this notification is behind the front of the stack     |
| `data-type`            | Root, Title, Description, Close, Action  | the notification has a `type`                          |
| `data-swiping`         | Root                                     | a swipe gesture is active                              |
| `data-swipe-direction` | Root                                     | the swipe direction (`up`/`down`/`left`/`right`)       |
| `data-swipe-dismiss`   | Root                                     | a release committed to dismissal                       |
| `data-side`, `data-align`, `data-uncentered` | Arrow                | Popper reports the corresponding placement or offset  |

The root also writes CSS variables for styling: `--toast-index`, `--toast-height`,
`--toast-offset-y`, and `--toast-swipe-movement-x` / `--toast-swipe-movement-y`.
The viewport exposes `--toast-frontmost-height` for the newest visible toast.

## API Reference

### RdxToastProvider

Hosts the `RdxToastManager` for its subtree (`[rdxToastProvider]`). `limit` defaults to `3` and
`timeout` defaults to `5000` milliseconds. `timeout: 0` disables automatic dismissal.

<ArgTypes of={RdxToastProvider} />

### RdxToastRoot

A single toast. Bind the toast model from the viewport's `@for`.

<ArgTypes of={RdxToastRoot} />

### RdxToastPositioner

Anchors a toast to an element via popper. Forwards the popper positioning inputs (`anchor`, `side`,
`sideOffset`, `align`, `alignOffset`, `arrowPadding`, `avoidCollisions`, `collisionPadding`, …).

<ArgTypes of={RdxToastPositioner} />

### Other parts

`RdxToastViewport`, `RdxToastContent`, `RdxToastTitle`, `RdxToastDescription`, `RdxToastClose`, and
`RdxToastAction` use the queue or their enclosing Root. `RdxToastPortal` forwards a `container`
input. `RdxToastArrow` uses its enclosing Positioner's arrow geometry.
