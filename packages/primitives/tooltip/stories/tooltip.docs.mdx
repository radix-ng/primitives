# Tooltip

#### Displays contextual information when a trigger is hovered or focused.

Tooltip composes the shared Popper, structural Portal (portal + presence), and Dismissable Layer
primitives. It remains headless: styles and native CSS animations belong to the consumer. The API
follows Base UI.

<Canvas sourceState="hidden" of={Stories.Default} />

## Features

- ✅ Opens on hover and keyboard focus, closes on blur, pointer leave, click, or Escape.
- ✅ Configurable open `delay`, `closeDelay`, and an instant-open `timeout` window.
- ✅ A `Provider` shares delays and the instant-open window across a group of tooltips.
- ✅ Supports uncontrolled state, `defaultOpen`, and Angular two-way binding with `[(open)]`.
- ✅ Supports multiple and detached triggers through a `Handle`.
- ✅ Can follow the cursor with `trackCursorAxis`.
- ✅ Positions content with the shared Floating UI-based Popper, with an optional custom `anchor`.
- ✅ Exposes `data-open`, `data-closed`, `data-side`, `data-align`, and a `data-instant` reason (`delay` / `dismiss` / `focus` / `tracking-cursor`) for styling.
- ✅ Keeps portal content mounted during CSS exit motion and supports persistent mounting.

## Anatomy

Apply the parts to your own markup. `rdxTooltipPortal` is a **structural** directive: it teleports its
content into `document.body` and keeps it mounted through the popup's CSS exit transitions or animations.
Use the `*` microsyntax on the positioner (or the explicit
`<ng-template rdxTooltipPortal>` form with `[container]` for a custom portal target):

```html
<ng-container rdxTooltip>
    <button rdxTooltipTrigger>+</button>

    <div *rdxTooltipPortal sideOffset="8" rdxTooltipPositioner>
        <div rdxTooltipPopup>Add to library</div>
        <span rdxTooltipArrow></span>
    </div>
</ng-container>
```

`rdxTooltipPositioner` owns positioning and exposes `data-side` / `data-align` plus the `--anchor-*`,
`--available-*`, and `--transform-origin` CSS variables. `rdxTooltipPopup` carries `role="tooltip"`.

## Open state

`defaultOpen` sets the initial uncontrolled state once. A supplied `[open]` value controls the popup,
including when it is `false`. Set `[open]` to `undefined` to return control to the root.

`(onOpenChange)` receives `{ open, eventDetails }` for a request. Call `eventDetails.cancel()` to veto
it. `(openChange)` emits the requested Boolean after an uncanceled request and supports `[(open)]`.
In a controlled tooltip, the popup and trigger description update when the parent changes `[open]`.
Parent writes emit neither request output. `RdxTooltip.open()` reads the effective state. To set state from
TypeScript in a controlled tooltip, update the value bound to `[open]`.

`(onOpenChangeComplete)` emits the effective Boolean after the popup finishes opening or closing.
It also follows changes to `[open]`. Call `eventDetails.preventUnmountOnClose()` in
`(onOpenChange)` to hold a close while custom motion runs. Export the root with
`#tooltip="rdxTooltip"` and call `tooltip.unmount()` to complete the held close.

Disabling the Root hides the popup and requests a close with reason `disabled` if its open state is
true. Re-enabling shows the popup again if that state was retained. Disable only the Trigger to
suppress hover and focus while keeping the popup available to `[open]`, as in the slider example.

## Active trigger

Assign an `id` to each trigger that shares a root. `defaultTriggerId` selects the initial trigger
for `defaultOpen`. Use `[triggerId]` to choose the trigger while the tooltip is open. Setting it to
`null` or `undefined` restores the local selection. An open tooltip with exactly one registered
trigger can select it automatically. With several triggers, set an ID or open from a trigger
interaction to establish the association.

`(triggerIdChange)` emits uncanceled requests to switch triggers and supports `[(triggerId)]`.
Changing the bound ID moves the anchor and updates the trigger description without emitting a
request. Read `triggerId()`, `trigger()` and `payload()` on the root to get the effective selection
and its current data. The same IDs work with detached triggers and `handle.open(id)`.

When the active trigger is removed, the root requests a close once the render has settled. A
replacement with the same ID keeps the tooltip open. A close veto retains the selection and its
last payload until that ID registers again or the selection changes.

### Provider

Wrap a group of tooltips with `rdxTooltipProvider` to share the open `delay`, `closeDelay`, and the
instant-open `timeout` window. Opening a sibling requests that the previous tooltip close. The
next hover skips its delay while the provider is active and until `timeout` ms after the last close.
`closeDelay` applies to hover. When focus leaves the trigger and popup, the close request uses reason
`trigger-focus`.

<Canvas of={Stories.Provider} />

### Per-trigger delay

Set `delay` (and `closeDelay`) on `rdxTooltipTrigger` to override the root, provider, and global
values for that trigger only.

### Disabled trigger

Set `disabled` on `rdxTooltipTrigger` (or `disabled` on `rdxTooltip` for all triggers). A disabled
trigger never opens the tooltip and reflects `data-trigger-disabled`.

Set `trackCursorAxis` on the root to `'x'`, `'y'`, or `'both'` to make the popup follow the pointer
along that axis.

## API Reference

### Root

`RdxTooltip` owns the open state, delays, cursor tracking, and detached-trigger association.

<ArgTypes of={RdxTooltip} />

### Provider

`RdxTooltipProvider` shares delays and the instant-open window across a group of tooltips.

<ArgTypes of={RdxTooltipProvider} />

### Trigger

`RdxTooltipTrigger` anchors the tooltip and exposes its open state through `data-popup-open`.

<ArgTypes of={RdxTooltipTrigger} />

**Data attributes**

| Attribute                | Present when                              |
| ------------------------ | ---------------------------------------- |
| `data-popup-open`        | This trigger's tooltip is open.          |
| `data-trigger-disabled`  | The trigger is disabled.                 |

`aria-describedby` points at the mounted popup's id while the tooltip is open.

### Portal

`RdxTooltipPortal` is a structural directive (`*rdxTooltipPortal` or `<ng-template rdxTooltipPortal>`)
that teleports content to `document.body` by default. Pass `[container]` on the explicit
`<ng-template>` form to portal into a different element.

Use `<ng-template rdxTooltipPortal keepMounted>` to preserve the same rendered view between opens.
The positioner becomes hidden and inert when the tooltip is closed and its exit has finished.

### Positioner

`RdxTooltipPositioner` delegates placement and collision handling to the shared Popper primitive. Its
optional `anchor` input overrides the trigger only for positioning.

<ArgTypes of={RdxTooltipPositioner} />

**Data attributes**

| Attribute            | Present when / value                                                       |
| -------------------- | ------------------------------------------------------------------------- |
| `data-open`          | The tooltip is open.                                                       |
| `data-closed`        | The tooltip is closed.                                                     |
| `data-side`          | Resolved side after collision handling — `top` / `right` / `bottom` / `left`. |
| `data-align`         | Resolved alignment — `start` / `center` / `end`.                          |
| `data-anchor-hidden` | The anchor is clipped/off-screen and the popup is hidden.                 |
| `data-instant`       | Placement changes can skip motion for this interaction.                    |

**CSS variables**

| Variable                                   | Description                                            |
| ------------------------------------------ | ----------------------------------------------------- |
| `--anchor-width` / `--anchor-height`       | Size of the anchor (trigger).                         |
| `--available-width` / `--available-height` | Space available before the collision boundary.        |
| `--transform-origin`                       | Origin to scale/zoom the popup from, based on side/align. |
| `--positioner-width` / `--positioner-height` | Target popup dimensions when a viewport measures the content. |

For viewport resize motion, size the positioner with `--positioner-width` and `--positioner-height`
and the popup with `--popup-width` and `--popup-height`. When the resolved physical side is
`top` or `left`, the positioner uses the far inset and aligns the popup along the edge nearest
the trigger as its size changes.

### Popup

`RdxTooltipPopup` carries `role="tooltip"` and reads its state from context.

**Data attributes**

| Attribute      | Present when / value                                                        |
| -------------- | -------------------------------------------------------------------------- |
| `data-open`    | The tooltip is open.                                                        |
| `data-closed`  | The tooltip is closed.                                                      |
| `data-starting-style` | The popup is in its initial entrance style.                           |
| `data-ending-style` | The popup is in its exit style.                                         |
| `data-side`    | Resolved side — `top` / `right` / `bottom` / `left`.                        |
| `data-align`   | Resolved alignment — `start` / `center` / `end`.                            |
| `data-instant` | The open/close was instant — `delay` / `dismiss` / `focus` / `tracking-cursor`. |

**CSS variables**

| Variable | Description |
| -------- | ----------- |
| `--popup-width` / `--popup-height` | Measured dimensions published when a viewport is present. |

### Viewport

Apply `rdxTooltipViewport` inside `rdxTooltipPopup` and give it one direct content wrapper.
The wrapper remains the live Angular view. When the active trigger changes, the viewport retains
an inert visual snapshot with the old `--popup-width` and `--popup-height` until its motion finishes.

**Data attributes**

| Attribute | Present when / value |
| --------- | -------------------- |
| `data-activation-direction` | On the viewport, a space-separated combination of `left`, `right`, `up` and `down`. |
| `data-transitioning` | On the viewport while both content layers are present. |
| `data-instant` | On the viewport for the root's instant interaction reason. |
| `data-current` | On the live content wrapper. |
| `data-previous` | On the outgoing snapshot. |
| `data-starting-style` | On the current wrapper before its entry transition. |
| `data-ending-style` | On the previous wrapper during its exit transition. |

### Arrow

`RdxTooltipArrow` reads its placement from context and points the popup at the anchor.

**Data attributes**

| Attribute         | Present when / value                                                        |
| ----------------- | -------------------------------------------------------------------------- |
| `data-open`       | The tooltip is open.                                                        |
| `data-closed`     | The tooltip is closed.                                                      |
| `data-side`       | Resolved side — `top` / `right` / `bottom` / `left`.                        |
| `data-align`      | Resolved alignment — `start` / `center` / `end`.                            |
| `data-instant`    | The open/close was instant — `delay` / `dismiss` / `focus` / `tracking-cursor`. |
| `data-uncentered` | The arrow was shifted from center to stay within the popup.                 |

## Accessibility

### Keyboard Interactions

| Key                     | Description                                                                  |
| ----------------------- | ---------------------------------------------------------------------------- |
| `Tab` / `Shift` + `Tab` | Moves focus onto the trigger (opening the tooltip) or away from it (closing it). |
| `Escape`                | Closes the open tooltip.                                                     |
