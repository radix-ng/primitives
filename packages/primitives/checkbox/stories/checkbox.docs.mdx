# Checkbox

#### A control that allows the user to toggle between checked and not checked.

<Primary />

## Features

- ✅ Full keyboard navigation.
- ✅ Supports indeterminate state.
- ✅ Can be controlled or uncontrolled.
- ✅ Native form submission with an optional native input for constraint validation.
- ✅ Base UI state hooks: `data-checked`, `data-unchecked`, and `data-indeterminate`.

## Import

```typescript
import {
  RdxCheckboxRootDirective,
  RdxCheckboxButtonDirective,
  RdxCheckboxIndicatorDirective,
  RdxCheckboxInputDirective
} from '@radix-ng/primitives/checkbox';
```

## Anatomy

Assemble the root, button trigger, and indicator. The native input is optional.

```html
<div rdxCheckboxRoot>
  <button rdxCheckboxButton>
    <svg rdxCheckboxIndicator lucideCheck />
  </button>
  <input rdxCheckboxInput />
</div>
```

A named root participates in `FormData` even without `[rdxCheckboxInput]`. Include the input when you
also need native constraint validation or bubbling browser `input` and `change` events.

### Labeling

Always associate a checkbox with a label. Link a sibling `rdxLabel` to the button with `htmlFor` / `id`:

```html
<div rdxCheckboxRoot>
  <button id="terms" rdxCheckboxButton>
    <svg rdxCheckboxIndicator lucideCheck />
  </button>
  <input rdxCheckboxInput />
</div>
<label rdxLabel htmlFor="terms">Accept terms and conditions</label>
```

When using `rdxFieldLabel`, point its `htmlFor` at the same button ID.

### Change events

`onCheckedChange` emits `{ checked, eventDetails }`; `rdxCheckboxGroup` emits `{ value, eventDetails }`.
A child or select-all checkbox emits first. The group receives the same event details if the child
accepts the request. Call `eventDetails.cancel()` in either handler to veto the edit.
Use `[controlledChecked]` or `[controlledValue]` when the parent decides which requests to apply.
Use `[(checked)]` or `[(value)]` for an editable Angular model. Angular form values and explicit
bindings take precedence over `defaultChecked` and `defaultValue`, which apply only at initialization.

```html
<div [controlledChecked]="checked()" (onCheckedChange)="setChecked($event)" rdxCheckboxRoot>
  ...
</div>
```

```ts
setChecked(change: RdxCheckboxCheckedChangeEvent) {
  if (this.readOnlyPolicy()) {
    change.eventDetails.cancel();
    return;
  }

  this.checked.set(change.checked);
}
```

### Indeterminate

`indeterminate` is a presentation input. A click or Space requests the opposite of the checked value.
To clear the mixed state after an accepted edit, update the value bound to `[indeterminate]` in your
`onCheckedChange` handler. Replace any `[(indeterminate)]` binding with that pattern.

There are two ways to build a "select all" parent. Pick by how much you want to own:

|                                  | **Select all** (below)                | **Checkbox group**                                                  |
| -------------------------------- | ------------------------------------- | ------------------------------------------------------------------- |
| Source of truth                  | your own model (one boolean per item) | the group's `string[]` value (the checked child values)            |
| Parent / indeterminate logic     | written by hand in the component      | built in (`parent` + `allValues`)                                   |
| Parent click                     | flat toggle: all ↔ none               | remembers the partial selection: partial → all → none → partial     |
| Disabled child during select-all | you handle it                         | preserved automatically                                             |
| Forms integration                | wire each control yourself            | the group is one control (`[(value)]` / `ngModel` / reactive forms) |

Reach for **Select all** when you already manage the items yourself and just need the derived parent
state. Reach for the **Checkbox group** when you want the array value and the Base UI parent behavior
for free.

### Select all

A parent checkbox derived from its children — `indeterminate` when only some are checked. Here the
parent/child logic (and the flat all ↔ none toggle) is wired **by hand** in the component.

<Canvas of={CheckboxStories.SelectAll} />

### Checkbox group

The same UI, but `rdxCheckboxGroup` owns it. It manages a single array value — the `value`s of the
checked checkboxes — and a child marked `parent` becomes the "select all", with its state derived
from `allValues`. Clicking the parent **remembers the partial selection** (partial → all → none →
back to the partial), and disabled selections are preserved. Bind the group's `string[]` value with
`[(value)]`, `ngModel`, or Reactive Forms. Give the group a `name` to submit its enabled selections
as repeated entries. With an unnamed group, each named child contributes its own native entry.
A child's `name` also supplies its group identity when `value` is omitted.

## Setup and shared files

These examples use Angular standalone components and Tailwind CSS v4. Install
`@radix-ng/primitives` and `@lucide/angular`. Copy the component from **Show code** and any shared files below,
preserving their relative import paths. Import the example component in its parent and use its selector.

Install `tailwindcss`, `@tailwindcss/postcss` and `postcss`. Configure the PostCSS plugin:

```json
{ "plugins": { "@tailwindcss/postcss": {} } }
```

Save the CSS below as `demo-styles.css` next to your global stylesheet. Import Tailwind first,
then the demo styles. Both Storybook and Playground use this same CSS through `main.css`.

```css
@import 'tailwindcss';
@import './demo-styles.css';
```

The shared file supplies theme values, light/dark tokens, common classes and animation keyframes.
Set `data-theme="dark"` on `<html>` for the dark theme; the default is light. The font stacks have
system fallbacks; Inter and JetBrains Mono can be self-hosted for the Storybook typography.

## API Reference

### Root

`RdxCheckboxRootDirective` coordinates checkbox state and form bindings. Apply it to a container
element such as a `<div>`. Use `nativeInput()` or `[inputRef]` to access an authored native input.

<ArgTypes of={RdxCheckboxRootDirective} />

**Data attributes**

| Attribute            | Present when                        |
| -------------------- | ----------------------------------- |
| `data-checked`       | The checkbox is checked.            |
| `data-unchecked`     | The checkbox is unchecked.          |
| `data-indeterminate` | The checkbox is in the mixed state. |
| `data-disabled`      | The checkbox is disabled.           |
| `data-readonly`      | The checkbox is read-only.          |
| `data-required`      | The checkbox is required.           |

### Button

Apply `RdxCheckboxButtonDirective` to a native `<button>`. Give it an `id` to associate a label.
Disabled buttons use native `disabled` and leave the tab order. Space toggles the checkbox.
Enter activates the owning form's default submit button, when present.

**Data attributes**

| Attribute            | Present when                        |
| -------------------- | ----------------------------------- |
| `data-checked`       | The checkbox is checked.            |
| `data-unchecked`     | The checkbox is unchecked.          |
| `data-indeterminate` | The checkbox is in the mixed state. |
| `data-disabled`      | The checkbox is disabled.           |
| `data-readonly`      | The checkbox is read-only.          |
| `data-required`      | The checkbox is required.           |

### Indicator

Apply `RdxCheckboxIndicatorDirective` to the mark element, such as an `<svg>`.
The directive retains the authored element and manages its layout visibility.

<ArgTypes of={RdxCheckboxIndicatorDirective} />

**Data attributes**

| Attribute             | Present when                             |
| --------------------- | ---------------------------------------- |
| `data-checked`        | The checkbox is checked.                 |
| `data-unchecked`      | The checkbox is unchecked.               |
| `data-indeterminate`  | The checkbox is in the mixed state.      |
| `data-disabled`       | The checkbox is disabled.                |
| `data-readonly`       | The checkbox is read-only.               |
| `data-required`       | The checkbox is required.                |
| `data-starting-style` | The indicator begins animating in. |
| `data-ending-style`   | The indicator is animating out.   |

### Input

Apply `RdxCheckboxInputDirective` to an optional native input for browser constraint validation and
`input` and `change` events. A named root also supports `FormData` serialization through the native
form bridge.

### Checkbox Group

`RdxCheckboxGroupDirective` (`rdxCheckboxGroup`) — a `role="group"` container holding the array of
checked child values. Mark a child checkbox `parent` to make it select/deselect every value in
`allValues`. A named group serializes selected values as repeated native form entries.

<ArgTypes of={RdxCheckboxGroupDirective} />

**Data attributes**

| Attribute       | Present when           |
| --------------- | ---------------------- |
| `data-disabled` | The group is disabled. |

## Accessibility

Mixed state is exposed as `aria-checked="mixed"`. See the [tri-state Checkbox WAI-ARIA design pattern](https://www.w3.org/WAI/ARIA/apg/patterns/checkbox).

### Keyboard Interactions

| Key     | Description                   |
| ------- | ----------------------------- |
| `Space` | Checks or unchecks the focused checkbox. |
| `Enter` | Activates the owning form’s default submit button, when present. |
