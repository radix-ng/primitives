# Tabs

#### A set of layered sections of content—known as tab panels—that are displayed one at a time.

<Canvas sourceState="hidden" of={TabsStories.Default} />

## Features

- ✅ Can be controlled or uncontrolled.
- ✅ Supports horizontal and vertical orientation.
- ✅ Supports automatic (on focus) and manual activation.
- ✅ Full keyboard navigation with composite focus.
- ✅ Optional active-tab indicator driven by CSS variables.
- ✅ Panels can stay mounted (and animate) or unmount when inactive.

## Import

```typescript
import {
    RdxTabsRoot,
    RdxTabsList,
    RdxTabsTab,
    RdxTabsPanel,
    RdxTabsPanelPresence,
    RdxTabsIndicator
} from '@radix-ng/primitives/tabs';
```

The aligned API follows [Base UI Tabs](https://base-ui.com/react/components/tabs): `Root` → `List` → `Tab`,
plus a `Panel` per value and an optional `Indicator`.

## Anatomy

```html
<div rdxTabsRoot>
    <div rdxTabsList>
        <button rdxTabsTab value="1"></button>
        <button rdxTabsTab value="2"></button>
        <span rdxTabsIndicator></span>
    </div>
    <div rdxTabsPanel value="1"></div>
    <div rdxTabsPanel value="2"></div>
</div>
```

## Change events

`onValueChange` emits `{ value, eventDetails }`. User-initiated changes use
`eventDetails.reason === 'none'` and can be rejected with `eventDetails.cancel()` before the selected value
changes. Automatic uncontrolled fallbacks use `'initial'`, `'disabled'`, or `'missing'`; these mirror Base UI
and are not cancelable. `eventDetails.activationDirection` reports `"left"`, `"right"`, `"up"`, `"down"`, or
`"none"`.

A defined `[value]` owns the selection. A request leaves that selection unchanged until the parent
updates its input; the parent can ignore the request, accept it later, or choose another value.
Rendered direction, Panels and Indicator follow the parent's actual selection. Use one-way `[value]`
with `onValueChange` when the parent decides how to handle a request:

```html
<div [value]="value()" (onValueChange)="setValue($event)" rdxTabsRoot>
    ...
</div>
```

```ts
setValue(change: RdxTabsValueChangeEvent) {
    if (this.hasUnsavedChanges()) {
        change.eventDetails.cancel();
        return;
    }

    this.value.set(change.value);
}
```

For automatic acceptance, use `[(value)]` with a defined initial application value. It pairs the
`value` input with `valueChange`; cancellation in `onValueChange` prevents that accepted-value output.

<Canvas of={TabsStories.Controlled} />

`valueChange` reports accepted requests and automatic uncontrolled changes. It does not report
external input updates or explicit default initialization. A controlled request can emit `valueChange`
while the input still holds the old selection. Choose one-way handling for delayed or transformed
responses; two-way binding automatically writes the requested value back into application state.

**Migration:** Root `value` is now a readonly signal, and `valueInput` supplies the native `value`
binding. Replace imperative `root.value.set()` / `.update()` with updates to the bound application
signal. Observe actual selection with `root.value()` in an Angular effect; `valueChange` observes
accepted requests. Initialize controlled application state explicitly. For uncontrolled tabs, omit
`[value]` and supply `defaultValue` when needed.

## Values

Tab values accept arbitrary identities, including objects, arrays, functions, symbols, `bigint` and
boolean. Objects and functions match by reference (`===`): keep the same value instance for a Tab,
its Panel and the selected value. Function values are stored and emitted as data.

`RdxTabsValue` and `onValueChange.value` now use `unknown`. When application state has a narrower
type, narrow the emitted value before updating it, as in this controlled example:

<Canvas of={TabsStories.ObjectValues} />

Root treats an omitted or `undefined` initial `value` as uncontrolled; an omitted or `undefined`
`defaultValue` uses `0`. A Tab and Panel can explicitly bind `undefined`, and a user request can
select that identity in an uncontrolled Root. Controlled Roots should keep their value defined.
An explicit `null` Tab/Panel matches a selected `null`; Indicator stays hidden for nullish values.
Values within a List must be unique under `===`, which treats `0` and `-0` as the same identity.
`NaN` does not match itself and should not be used as a selectable identity.

## Dynamic tabs

In uncontrolled tabs, removing or disabling the selected tab chooses the first enabled tab. Emptying
a previously populated List, or disabling the selection with no enabled tabs left, selects `null`.
Adding or enabling tabs later preserves that null selection until a user activates a tab.
Removing the whole List temporarily preserves the
selected value. Replacing a populated List or the selected tab's element preserves a value that still
exists. Controlled values are not automatically corrected when the collection changes.

An explicit disabled `defaultValue` stays selected until that tab has been enabled; disabling it again
then uses the normal fallback. Reordering existing tabs preserves their native focus and keyboard
position. Restoring focus after a view move does not request automatic activation again.

## Examples

### Activate on focus

Set `activateOnFocus` on the list to activate a tab as soon as it receives keyboard focus (automatic
activation). By default activation is manual — tabs activate on click or `Enter` / `Space`.

<Canvas of={TabsStories.ActivateOnFocus} />

### Vertical

Set `orientation="vertical"` on the root to lay the tabs out vertically and switch arrow-key navigation
to `ArrowUp` / `ArrowDown`.

<Canvas of={TabsStories.Vertical} />

### Disabled

A disabled tab remains reachable by composite keyboard navigation, but it cannot be activated.

<Canvas of={TabsStories.Disabled} />

### Indicator

`RdxTabsIndicator` exposes the active tab's geometry as CSS variables, so a single element can animate to
follow the selected tab.

Its host has `role="presentation"` and stays mounted but hidden when no selected tab has a nonzero
size. It updates when the List or any tab resizes, including when a label changes.

<Canvas of={TabsStories.Indicator} />

### Animated panels

Panels stay mounted by default in Angular, so you can cross-fade them with the `data-starting-style`,
`data-ending-style` and `data-hidden` attributes — the panel keeps itself visible until the transition
finishes. Inactive panels are immediately inert, including during an exit, so their contents cannot
receive focus or pointer input. `data-hidden` is applied after the exit settles; use
`data-ending-style` to start exit motion.

<Canvas of={TabsStories.Animated} />

### Mounting & unmounting

An ordinary `rdxTabsPanel` stays in the DOM and is hidden while inactive. Apply
`*rdxTabsPanelPresence="value"` to the panel host to create only the active Panel view and destroy
the complete view after its exit finishes. Its Angular children are destroyed as well; returning
creates new children. The structural directive supplies the value to `rdxTabsPanel`.
Use `keepMounted: true` on the structural directive to retain the whole view and its child state.

```html
<!-- Unmount when inactive -->
<div *rdxTabsPanelPresence="'one'" rdxTabsPanel>Panel one</div>

<!-- Keep mounted (hidden) when inactive -->
<div *rdxTabsPanelPresence="'two'; keepMounted: true" rdxTabsPanel>Panel two</div>
```

### Unmount with `@keyframes`

With `*rdxTabsPanelPresence`, the shared render lifetime observes the Panel and explicit
`rdxPresenceTarget` descendants before destroying the whole view. Import `RdxPresenceTarget` for an
animated inner element. Mark the panel as a `group` so the
inner element can react to the parent's `data-ending-style` and run the exit keyframes. The panel
stays visible and inert until removal. Its ID belongs to the structural instance and stays stable
when the native Panel is recreated.

**Migration:** move the former inner `*rdxTabsPanelPresence` onto the Panel host, move its `value`
into the structural expression and move structural `keepMounted` into the microsyntax above.
The former argument-free inner presence syntax is no longer supported.

<Canvas of={TabsStories.KeyframeUnmount} />

### Projected through a wrapper

Tabs can be projected into a list owned by a wrapper component's view. The wrapper composes
`RdxTabsRoot` onto its host and keeps `RdxTabsList` in its template; projected tabs still participate
in roving focus and implicit selection.

## API Reference

### TabsRoot

`RdxTabsRoot` — groups the tabs and their panels.

| Data attribute              | Value                                           |
| --------------------------- | ----------------------------------------------- |
| `[data-orientation]`        | `"horizontal" \| "vertical"`                    |
| `[data-activation-direction]` | `"left" \| "right" \| "up" \| "down" \| "none"` |

### TabsList

`RdxTabsList` — groups the tab buttons and owns composite keyboard focus.

<ArgTypes of={RdxTabsList} />

| Data attribute                | Value                                           |
| ----------------------------- | ----------------------------------------------- |
| `[data-orientation]`          | `"horizontal" \| "vertical"`                    |
| `[data-activation-direction]` | `"left" \| "right" \| "up" \| "down" \| "none"` |

### TabsTab

`RdxTabsTab` — an interactive tab that activates its panel. Apply to a native `<button>` element.

Set `[nativeButton]="false"` when using another host, such as a `<div>` or `<a>`. Enter uses native
button/link activation; other hosts receive a keyboard click. Space activates on keydown through
one click and prevents page scrolling. Disabled tabs remain arrow-focusable and suppress activation,
including native primary link navigation. Native button hosts default to `type="button"`.
Set `type="submit"` or `type="reset"` to preserve that native form action alongside tab selection.
Middle-click navigation on link hosts remains native, including when the tab is disabled.

Reject a selection with `eventDetails.cancel()` in `onValueChange`; a canceled keyboard request does
not get retried by the keyup default. For links, selection cancellation and native navigation are
separate: prevent the native event default as well when you want to cancel navigation.

Tab and Panel each receive an SSR-stable, unique ID for their lifetime. Changing `value` keeps that
ID; replacing the element generates a new one. Set `id` on either part to use your own native ID.
`aria-controls` and `aria-labelledby` follow the registered parts and update when their IDs change.
Removing a part removes the corresponding reference.

<ArgTypes of={RdxTabsTab} />

| Data attribute                | Value                                           |
| ----------------------------- | ----------------------------------------------- |
| `[data-active]`               | Present when the tab is active.                 |
| `[data-disabled]`             | Present when the tab is disabled.               |
| `[data-orientation]`          | `"horizontal" \| "vertical"`                    |
| `[data-activation-direction]` | `"left" \| "right" \| "up" \| "down" \| "none"` |

### TabsPanel

`RdxTabsPanel` — content shown when its tab is active.

Apply to a container element, typically a `<div>`. Its `id` is the target of the matching Tab's
`aria-controls` while the host exists. Whole-Panel presence unregisters that target when its view is
destroyed and restores it on return. With structural presence, value and mounting policy come from
the structural directive; an ordinary retained Panel takes its own `value` input.

<ArgTypes of={RdxTabsPanel} />

| Data attribute                | Value                                           |
| ----------------------------- | ----------------------------------------------- |
| `[data-hidden]`               | Present when the inactive panel's exit has finished. |
| `[data-index]`                | Numeric index of the panel.                     |
| `[data-starting-style]`       | Present while the enter transition runs.        |
| `[data-ending-style]`         | Present while the exit transition runs.         |
| `[data-orientation]`          | `"horizontal" \| "vertical"`                    |
| `[data-activation-direction]` | `"left" \| "right" \| "up" \| "down" \| "none"` |

### TabsPanelPresence

`*rdxTabsPanelPresence` — apply to the same element as `rdxTabsPanel` to own the complete Panel view.
The structural value associates it with a Tab; `keepMounted` retains its inactive view. Exit motion
can keep an outgoing view mounted and inert until completion.

<ArgTypes of={RdxTabsPanelPresence} />

### TabsIndicator

`RdxTabsIndicator` — exposes the active tab's geometry. Apply it to a `<span>` inside the List.

<ArgTypes of={RdxTabsIndicator} />

With SSR, opt into `renderBeforeHydration` to position the Indicator before Angular starts:

```html
<span rdxTabsIndicator renderBeforeHydration></span>
```

The option defaults to `false`. Its server-only inline script uses Angular's `CSP_NONCE` when
provided. It waits for nonzero dimensions; transformed tabs use normal client measurement. The
server-positioned Indicator stays visible through hydration. CSR uses the normal render hooks.

**Data attributes**

| Attribute                   | Present when / value                                          |
| --------------------------- | ------------------------------------------------------------ |
| `data-orientation`          | The tabs orientation — `horizontal` / `vertical`.            |
| `data-activation-direction` | Direction the selection last moved — `left`/`right`/`up`/`down`/`none`. |

**CSS variables** (the active tab's geometry, so one element can animate between tabs):

Positions use List-local CSS pixels, accounting for its borders, scrolling and ancestor transforms.
A tab's own translation is followed; its own rotation or scale
keeps the indicator at the tab's untransformed layout slot. Right/bottom distances use the List's
scrollable content dimensions.

| CSS variable           | Description                          |
| ---------------------- | ------------------------------------ |
| `--active-tab-top`     | Distance from the top of the list.   |
| `--active-tab-right`   | Distance from the right of the list. |
| `--active-tab-bottom`  | Distance from the bottom of the list.|
| `--active-tab-left`    | Distance from the left of the list.  |
| `--active-tab-width`   | Width of the active tab.             |
| `--active-tab-height`  | Height of the active tab.            |

## Accessibility

Adheres to the [Tabs WAI-ARIA design pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs).

### Keyboard Interactions

| Key          | Description                                                                                          |
| ------------ | --------------------------------------------------------------------------------------------------- |
| `Tab`        | Moves focus onto the active tab. From a tab, moves focus to the active panel.                        |
| `ArrowDown`  | (Vertical) Moves focus to the next tab.                                                              |
| `ArrowRight` | (Horizontal) Moves focus to the next tab.                                                            |
| `ArrowUp`    | (Vertical) Moves focus to the previous tab.                                                          |
| `ArrowLeft`  | (Horizontal) Moves focus to the previous tab.                                                        |
| `Home`       | Moves focus to the first tab, including a disabled tab.                                              |
| `End`        | Moves focus to the last tab, including a disabled tab.                                               |
| `Enter` / `Space` | Activates the focused tab (always, and the only way to activate when `activateOnFocus` is off). |
