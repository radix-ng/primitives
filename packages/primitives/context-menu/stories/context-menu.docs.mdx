# Context Menu

#### A menu that appears at the pointer on right click (or touch long-press), built on the Menu primitive.

Context Menu reuses the full [Menu](?path=/docs/primitives-menu--docs) primitive for its popup,
items, submenus, checkbox/radio items, and separators. The only difference is the trigger: instead
of a button that anchors the popup to itself, `rdxContextMenuTrigger` opens the menu at the pointer
position on a right click or long-press.

Set `disabled` on `rdxContextMenuRoot` to disable the whole menu, including every context area and
imperative opening. Closing restores the element focused before opening; the right-click area is
not necessarily focusable or focused by the browser. `finalFocus` on the popup overrides that policy.

## Features

- ✅ Opens at the pointer on right click; on touch, opens after a long-press.
- ✅ Suppresses the native browser context menu.
- ✅ Reuses every Menu popup part — items, submenus, checkbox/radio items, groups, separators.
- ✅ Native pointer and keyboard context-menu opening focus the popup without highlighting an item; arrow keys enter the list.
- ✅ Full keyboard navigation once open (ArrowDown / ArrowUp / Home / End / typeahead).
- ✅ Closes on Escape, outside pointer interaction, and item selection — restoring focus.
- ✅ Headless — state is exposed via `data-popup-open` / `data-pressed`; styling is up to the consumer.

Long-press waits 500 ms by default. Moving more than 10 px on either axis, native cancellation,
or a second finger cancels the pending request. Diagonal movement within 10 px per axis remains
eligible. A touch anchor is 10 × 10 px; pointer/keyboard context-menu events use a point anchor.

## Import

```typescript
import { RdxContextMenuRoot, RdxContextMenuTrigger } from '@radix-ng/primitives/context-menu';
import { RdxMenuModule } from '@radix-ng/primitives/menu';
```

Or import the context-menu parts through the module:

```typescript
import { RdxContextMenuModule } from '@radix-ng/primitives/context-menu';
```

## Anatomy

Wrap the trigger area and the Menu popup in a `rdxContextMenuRoot`. The popup is assembled from the
standard Menu parts and positioned at the pointer, so `rdxMenuPositioner` needs no `anchor`.

```html
<ng-container #root="rdxContextMenuRoot" rdxContextMenuRoot>
  <div rdxContextMenuTrigger>Right click here</div>

  <div *rdxMenuPortal rdxMenuPositioner>
    <div rdxMenuPopup>
      <button rdxMenuItem>Back</button>
      <button rdxMenuItem>Reload</button>

      <div rdxMenuSeparator></div>

      <!-- submenu -->
      <ng-container #sub="rdxMenuRoot" rdxMenuRoot>
        <button rdxMenuSubTrigger>More Tools ›</button>
        <div *rdxMenuPortal side="right" align="start" rdxMenuPositioner>
          <div rdxMenuPopup>
            <button rdxMenuItem>Save Page As…</button>
          </div>
        </div>
      </ng-container>
    </div>
  </div>
</ng-container>
```

### Radio

Use Menu radio groups for independent, exclusive choices. Each group has an associated label;
its selected item has a centered indicator and the same text inset as the label. Selection stays
open and updates the Angular signals shown below the area. The Theme group is example state;
the Storybook toolbar controls the preview theme.

### Sides

Set `side` on `rdxMenuPositioner` to prefer `top`, `right`, `bottom`, or `left` relative to the
pointer anchor. Each area owns an independent menu. `sideOffset` leaves a gap, and collision
avoidance can flip the popup when its preferred side has insufficient space.

<Canvas sourceState="hidden" of={Stories.Sides} />

### Shared menu across areas

Place several `rdxContextMenuTrigger` areas inside one Root to reuse the same popup at each native
gesture's coordinates. Context areas remain separate from Menu trigger registration and ARIA identity.
Their open/pressed attributes reflect the shared menu state, rather than an active-area payload.

<Canvas sourceState="hidden" of={Stories.MultipleAreas} />

### Nested context areas

The nearest context area owns a right-click or touch long-press. It consumes the native gesture even
when an application cancels opening, so the parent area cannot issue a second request.
Submenus use the standard Menu parts: Escape closes the deepest submenu and selection closes the chain.

Canceling an outside close keeps the current area session and anchor. A gesture can produce separate
pointerdown/mousedown requests; keep your veto policy active until retry is allowed.

## Accessibility

### Keyboard Interactions

Native pointer and keyboard context-menu events focus the popup without highlighting an item,
matching Base UI. Press `ArrowDown` / `ArrowUp` to enter the list. The Menu key and `Shift` + `F10`
follow native browser/OS support; the primitive does not synthesize unavailable platform events.
Applications calling `root.openAt(x, y, 'first')` can explicitly choose initial item focus.
The popup then behaves like a [Menu](?path=/docs/primitives-menu--docs):
`ArrowDown` / `ArrowUp` move between items, `Home` / `End` jump to the first / last item, typeahead matches
item text, and `Escape` closes the menu.

## API Reference

### RdxContextMenuRoot

Groups all parts of the context menu and provides the Menu context consumed by the popup. Composes
the Menu primitive, so it forwards the `open` (two-way), `disabled`, `modal`, `loopFocus`, and
`highlightItemOnHover` inputs and the `onOpenChange` / `onOpenChangeComplete` outputs from
`rdxMenuRoot`.

The exported root exposes `close()` and `unmount()` through the shared Menu lifecycle. Request an
external exit with `eventDetails.preventUnmountOnClose()` in `(onOpenChange)`, then call
`root.unmount()` when that animation finishes. `close()` defaults to the reason `imperative-action`.
Completion follows actual portal exit; `keepMounted` retains the settled view without delaying it.

Removing the whole Root with `@if` destroys its popup and submenus, including retained views and
unfinished exits, and releases background interaction and scroll locking. Removal emits no extra
close request or unfinished-exit completion. Set the popup's `finalFocus` to a surviving outside
control when the original focus target is removed with the Root.

### RdxContextMenuTrigger

The area that opens the menu on right click or touch long-press.

<ArgTypes of={RdxContextMenuTrigger} />

**Data attributes**

| Attribute           | Present when                          |
| ------------------- | ------------------------------------- |
| `data-popup-open`   | The context menu is open.             |
| `data-pressed`      | The context menu is open.               |
| `data-disabled`     | The trigger is disabled.              |

### Menu parts

All other parts — `rdxMenuPositioner`, `rdxMenuPopup`, `rdxMenuItem`, `rdxMenuCheckboxItem`,
`rdxMenuRadioGroup`, `rdxMenuSubTrigger`, `rdxMenuSeparator`, … — come from the
[Menu](?path=/docs/primitives-menu--docs) primitive and behave identically here.
