# Portal

#### Renders its host element into a different part of the DOM (`document.body` by default).

The badge is declared inside a clipping box, yet `rdxPortal` renders it under `document.body`, so it escapes
`overflow: hidden` and pins to the viewport corner.

## Features

- ✅ Teleports the element it is attached to out of the normal document flow.
- ✅ Appends to `document.body` by default, or to an HTML element or ShadowRoot.
- ✅ Reactive container — changing the target moves the element to the new container.
- ✅ Restores the element to its original position when destroyed.
- ✅ SSR safe — does nothing on the server.

## Anatomy

`rdxPortal` is an attribute directive applied directly to the element you want to teleport.

```html
<div rdxPortal>This content is moved to the document body.</div>
```

## Basic Usage

Add `rdxPortal` to any element. On the browser it is detached from its current position and appended to
`document.body`, leaving a comment node behind as an anchor so it can be put back on destroy.

```typescript
import { Component } from '@angular/core';
import { RdxPortal } from '@radix-ng/primitives/portal';

@Component({
    selector: 'app-example',
    imports: [RdxPortal],
    template: `
        <div class="card">
            <h2>Card</h2>

            <!-- Rendered under <body>, not inside .card -->
            <div rdxPortal class="overlay">Portaled content</div>
        </div>
    `
})
export class ExampleComponent {}
```

## Custom Container

Use the `container` input to portal into a specific element instead of `document.body`. It accepts an
`ElementRef` of an HTML element or ShadowRoot, a native `HTMLElement` or `ShadowRoot`, or a CSS selector
string resolved against the declaring document. Elements from same-origin iframes are accepted. When a
selector matches nothing, it falls back to `document.body`. The move is reactive: if the bound container
changes later, the element is relocated to the new one.

An omitted container or `undefined` uses the default container. Explicit `null` waits for a target:
in the browser, the attribute Portal detaches its host while retaining its Angular view and edited
values. Structural portals such as `rdxMenuPortal` do not create their embedded view while waiting,
even with `keepMounted`. Changing a structural Portal to `null` destroys that view immediately and
cancels an exit wait; a later target creates a fresh view. The attribute Portal still renders in
place on the server, while a pending structural Portal emits no content.

For a signal query, bind `[container]="host()?.nativeElement ?? null"`. Query changes drive target
availability; Portal does not poll mutable ref objects or wait for a missing CSS selector.

The element and its Angular view are moved together. Existing form values and focus within the moved
view are preserved. Structural portals such as `rdxMenuPortal` use the same target resolver and move
their existing view rather than recreating it. Moving an open Menu therefore keeps its current item
and does not emit another opening completion.

Install the required styles in the destination document or shadow tree; Portal does not copy stylesheets.
CSS selectors do not traverse iframe or shadow boundaries, so pass those DOM targets directly or through
an `ElementRef`. Cross-document transfer of ordinary content is supported. For interactive overlays,
keep the Root, trigger and popup in the same document and tree so native labels, ARIA id references and
keyboard ownership can resolve together; mixed-document overlays need separate verification.

### Server rendering and deferred content

Portal content renders at its declaration on the server and moves after its owning view renders in
the browser. Angular can hydrate `@defer` islands independently: a Portal does not wait for every
island on the page. Existing server nodes, input edits and their generated IDs are retained.

Structural portals also move still-dehydrated roots and roots materialized later by `@defer`, `@if`
or `@for`. Changing a ready destination moves the current content. These views use inert
Angular-managed template boundaries; keep those boundaries and the SSR metadata intact. Content
elements remain direct children of the destination, with no layout wrapper.

Angular 22 can retain a pending hydration task when an already hydrating `@defer` is destroyed
during its lazy import; an ordinary `@if` reproduces this limitation. Portal removes its owned DOM,
but cannot complete Angular's private hydration task. Keep the view mounted until hydration finishes
if your application needs `ApplicationRef.whenStable()` to resolve through that cancellation.

```typescript
import { Component, ElementRef, viewChild } from '@angular/core';
import { RdxPortal } from '@radix-ng/primitives/portal';

@Component({
    selector: 'app-example',
    imports: [RdxPortal],
    template: `
        <div #portalHost class="portal-host"></div>

        @if (host(); as target) {
            <!-- ElementRef -->
            <div rdxPortal [container]="target">Rendered inside .portal-host</div>

            <!-- Native element -->
            <div rdxPortal [container]="target.nativeElement">…</div>
        }

        <!-- CSS selector -->
        <div rdxPortal container=".portal-host">…</div>
    `
})
export class ExampleComponent {
    readonly host = viewChild<ElementRef<HTMLElement>>('portalHost');
}
```

The query guard defers mounting until the target exists. Use the same approach for a queried
ShadowRoot host or an iframe that has not finished loading.

You can also change the container imperatively via the exported instance:

```html
<div rdxPortal #portal="rdxPortal">…</div>
```

```typescript
portal.setContainer(someElementRef);
```

## Notes

- The directive moves **the element it is attached to**, so place `rdxPortal` on the element you want to teleport.
- On destroy the element is returned to its original position (tracked by an internal comment anchor), so Angular
  can tear the view down cleanly.
- The default container is `document.body`; the provided `container` takes precedence when set.
