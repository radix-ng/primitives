# Radio Group

#### A set of checkable buttons—known as radio buttons—where no more than one of the buttons can be checked at a time.

<Canvas sourceState="hidden" of={RadioDirectiveStories.Default} />

## Features

- ✅ Full keyboard navigation.
- ✅ Can be controlled or uncontrolled.

## Import

Get started with importing the directives:

```typescript
import {
    RdxRadioGroupDirective,
    RdxRadioIndicatorDirective,
    RdxRadioIndicatorPresenceDirective,
    RdxRadioItemDirective,
    RdxRadioItemInputDirective
} from '@radix-ng/primitives/radio';
```

## Anatomy

```html
<div rdxRadioRoot name="density">
  <label>
    <span rdxRadioItem value="default">
      <span *rdxRadioIndicatorPresence rdxRadioIndicator></span>
      <input rdxRadioItemInput />
    </span>
    Default
  </label>
</div>
```

A named group submits the value of its mounted, enabled selected item. Add
`input[rdxRadioItemInput]` inside each item for native `required` validation,
`<label>` activation or native input/change events. Failed native validation focuses the
visible radio. Use `form="form-id"` on the group to associate it with a form elsewhere on
the page. Click, keyboard selection and Angular Forms work with or without item inputs.
See [Field composition](#field-composition) for shared form state and label wiring.
See [Validation timing](#validation-timing) for Angular Forms and Field.
See [Option values](#option-values) for numbers, objects and arrays.
See [Native input refs](#native-input-refs) for access to authored inputs.

The item can attach to any element. When the host is a native `<button>` it is detected automatically:
`type="button"` and the native `disabled` attribute are applied for you — there is no `nativeButton`
input to set.

## Field composition

Import `RdxFieldRoot`, `RdxFieldLabel`, `RdxFieldDescription` and `RdxFieldItem` from
`@radix-ng/primitives/field` to associate a group label and description and give each item
its own label. Use a non-native label for the group and a native label for each item's input.

```html
<div rdxFieldRoot name="density">
    <span rdxFieldLabel>Density</span>
    <p rdxFieldDescription>Choose how much space to leave between rows.</p>

    <div rdxRadioRoot>
        <div rdxFieldItem>
            <span rdxRadioItem value="compact">
                <span rdxRadioIndicator></span>
                <input rdxRadioItemInput />
            </span>
            <label rdxFieldLabel>Compact</label>
        </div>
        <div rdxFieldItem>
            <span rdxRadioItem value="comfortable">
                <span rdxRadioIndicator></span>
                <input rdxRadioItemInput />
            </span>
            <label rdxFieldLabel>Comfortable</label>
        </div>
    </div>
</div>
```

The field's name takes precedence over the group's name. A disabled field disables the group,
and a disabled Field Item disables its radio. Each radio includes the group description and
its own Field Item description.

The group uses its explicit `aria-labelledby`, the Field label, or the enclosing Fieldset's
`legend[rdxFieldsetLegend]`, in that order. Import `RdxFieldsetRoot` and `RdxFieldsetLegend` from
`@radix-ng/primitives/fieldset` to share a legend with related controls.

| Attribute      | Parts                                     | Present when                         |
| -------------- | ----------------------------------------- | ------------------------------------ |
| `data-valid`   | RadioGroup, RadioGroupItem, RadioIndicator | Field displays a valid state.        |
| `data-invalid` | RadioGroup, RadioGroupItem, RadioIndicator | Field displays an invalid state.      |
| `data-filled`  | RadioGroup, RadioGroupItem, RadioIndicator | Field has a selection.                |
| `data-focused` | RadioGroup, RadioGroupItem, RadioIndicator | An enabled radio has focus.           |
| `data-dirty`   | RadioGroup, RadioGroupItem, RadioIndicator | Field is dirty.                       |
| `data-touched` | RadioGroup, RadioGroupItem, RadioIndicator | Field is touched.                     |

## Initial selection and reset

`defaultValue` initializes the selection once when the group has no value binding, Angular form
value or `controlledValue`. A supplied `null` means no selection, and `''` can select an item with an empty string value.
Changes to `defaultValue` after initialization leave the current selection in place.

Use `[(value)]` when binding the editable model directly. Use `ngModel`, a Reactive Forms control,
or Signal Forms when a form owns the value. A native form reset restores the initial selection of
a standalone group. A connected `NgControl` uses its own reset baseline, and Signal Forms
`reset()` uses the field's reset contract. A parent-owned selection stays in effect on native reset.
A composed Field reflects the resulting selection in `data-filled`, including an empty-string
option. Canceling a native reset preserves the selection and interaction state.

## Validation timing

When using Reactive Forms, add `rdxNgControlField` alongside `[formControl]` on the Radio Group
inside `rdxFieldRoot`. Validators live on the Angular control. Field's `validationMode` controls
when the group, items and indicators show its validation state.

- `onBlur` reveals errors when focus leaves the group. Moving between its radios keeps the
  validation state hidden until that boundary.
- `onChange` reveals the state after a committed value change, including a programmatic write.
  Returning to the initial value also displays its resulting validity.
- `onSubmit` reveals errors on a submit attempt from `rdxFormRoot` and updates the display after
  subsequent edits.

A Reactive Forms control configured with `updateOn: 'blur'` commits pending selections when focus
leaves the group. Field then reflects the committed form value.

## Option values

Give each item a distinct value. Numbers and strings are separate values, and objects and arrays
compare by reference. Reuse the same object or array in the item binding and the selected value.
`null` represents no selection. Use `[value]` for a value with a type other than string.

```ts
import { Component, signal } from '@angular/core';
import { RdxRadioGroupDirective, RdxRadioItemDirective } from '@radix-ng/primitives/radio';

interface StorageOption {
    id: string;
    label: string;
}

@Component({
    selector: 'storage-options',
    imports: [RdxRadioGroupDirective, RdxRadioItemDirective],
    template: `
        <div [controlledValue]="selected()" (onValueChange)="selected.set($event.value)" rdxRadioRoot aria-label="Storage">
            @for (option of options; track option.id) {
                <button [value]="option" rdxRadioItem>{{ option.label }}</button>
            }
        </div>
    `
})
export class StorageOptions {
    protected readonly options: StorageOption[] = [
        { id: 'standard', label: 'Standard' },
        { id: 'premium', label: 'Premium' }
    ];
    protected readonly selected = signal<StorageOption | null>(this.options[0] ?? null);
}
```

The Angular form model and `onValueChange` retain the original value.
Use `RdxRadioValueChangeEvent<StorageOption>` when annotating an object-valued handler.
A native form submits one entry for the selection. Strings pass through, and other values
are serialized as JSON where possible. Two distinct items can produce the same submitted string.
Give independent groups separate form owners or distinct names if they use native radio inputs.

## Selection ownership and change events

`onValueChange` requests a selection through `{ value, eventDetails }`. The details include the
`reason`, originating DOM event, and radio item that triggered the request. Call `eventDetails.cancel()`
to veto the edit. `[(value)]` and the Angular form adapters commit accepted local edits automatically.

Use `[controlledValue]` when the application decides what to commit. It can ignore the request,
apply it later, or supply a different selection. A defined `controlledValue`, including `null`, owns
the rendered and submitted selection. Read that selection through `currentValue()` on the group.

```html
<div [controlledValue]="value()" (onValueChange)="setValue($event)" rdxRadioRoot>
    ...
</div>
```

```ts
setValue(change: RdxRadioValueChangeEvent) {
    if (this.preventSelection(change.value)) {
        change.eventDetails.cancel();
        return;
    }

    this.value.set(change.value);
}
```

Use either application ownership or an editable Angular form binding for the group. Setting
`controlledValue` to `undefined` returns to the editable value. The two modes keep their own
input values, and switching modes does not reapply `defaultValue`.

With `rdxRadioItemInput`, an accepted editable activation emits one `input` and one `change`.
External value writes update the checked input and `FormData` without emitting native edit events.

## Native input refs

Bind `[inputRef]` on `rdxRadioRoot` for the group's representative native radio input,
or on `rdxRadioItem` for that item's own input.

```ts
import { Component, signal } from '@angular/core';
import { RdxRadioGroupDirective, RdxRadioItemDirective, RdxRadioItemInputDirective } from '@radix-ng/primitives/radio';

@Component({
    selector: 'density-options',
    imports: [RdxRadioGroupDirective, RdxRadioItemDirective, RdxRadioItemInputDirective],
    template: `
        <div [inputRef]="setInput" rdxRadioRoot defaultValue="compact" aria-label="Density">
            <span rdxRadioItem value="compact">Compact<input rdxRadioItemInput /></span>
            <span rdxRadioItem value="comfortable">Comfortable<input rdxRadioItemInput /></span>
        </div>
    `
})
export class DensityOptions {
    readonly nativeInput = signal<HTMLInputElement | null>(null);
    protected readonly setInput = (element: HTMLInputElement | null) => this.nativeInput.set(element);
}
```

The group forwards the enabled selected input when available. On initialization and clearing,
it can use the first eligible authored input. Removing or disabling the forwarded input releases
the binding. A selected input or a newly eligible registration can then take its place.

Both directives expose a readonly `nativeInput()` signal. The input comes from
`input[rdxRadioItemInput]`. The group's generated form-data fallback does not appear in either ref.
Callbacks run after browser rendering. When the element or callback changes, the old binding
receives `null` or runs the cleanup function its callback returned.

## API Reference

### RadioGroup

`RdxRadioGroupDirective` — owns the shared radio state and form metadata. Apply to a container element
(typically a `<div>`). Exposes `role="radiogroup"` and mirrors `aria-required` / `aria-disabled` /
`aria-readonly`.

<ArgTypes of={RdxRadioGroupDirective} />

**Data attributes**

| Attribute       | Present when             |
| --------------- | ------------------------ |
| `data-disabled` | the group is disabled.   |
| `data-required` | the group is required.   |
| `data-readonly` | the group is read-only.  |

### RadioGroupItem

`RdxRadioItemDirective` — one radio button. Apply to an element that represents the button: a `<span>`,
or a native `<button>` (detected automatically, which applies `type="button"` and native `disabled`).
Exposes `role="radio"` and `aria-checked`.

<ArgTypes of={RdxRadioItemDirective} />

**Data attributes**

| Attribute        | Present when                          |
| ---------------- | ------------------------------------- |
| `data-checked`   | the radio is selected.                |
| `data-unchecked` | the radio is not selected.            |
| `data-disabled`  | the radio or its group is disabled.   |
| `data-readonly`  | the radio or its group is read-only.  |
| `data-required`  | the radio or its group is required.   |
| `data-composite-item-active` | the radio is the active (selected) composite item. |

### RadioGroupItemInput

`RdxRadioItemInputDirective` — optional hidden native radio input for constraint validation,
`<label>` activation, and native input/change events. Apply it inside an item. Its default ID
is the item ID followed by `-input`. Set `id` to use your own ID with an explicit label.

### RadioIndicator

`RdxRadioIndicatorDirective` — visual marker shown when the radio is selected. Apply to an element
inside an item (typically a `<span>`). Used on its own, the attribute directive hides the authored
host after exit. Set `keepMounted` on the host to leave it displayed while unchecked.
Use `data-checked` and `data-unchecked` for styles that should persist after motion.

<ArgTypes of={RdxRadioIndicatorDirective} />

**Data attributes**

| Attribute             | Present when                                            |
| --------------------- | ------------------------------------------------------ |
| `data-checked`        | the radio is selected.                                 |
| `data-unchecked`      | the radio is not selected.                             |
| `data-disabled`       | the radio or its group is disabled.                    |
| `data-readonly`       | the radio or its group is read-only.                   |
| `data-required`       | the radio or its group is required.                    |
| `data-starting-style` | the indicator is entering after a selection change.    |
| `data-ending-style`   | the indicator is exiting after deselection.            |

### RadioIndicatorPresence

`RdxRadioIndicatorPresenceDirective` — owns the indicator's Angular view. Apply
`*rdxRadioIndicatorPresence` to the element with `rdxRadioIndicator`. The view is created when
selected and destroyed after the indicator's CSS exit finishes. Selecting it again during exit
preserves that view. An initially selected radio renders its indicator in the settled state.

```html
<span *rdxRadioIndicatorPresence rdxRadioIndicator></span>
<span *rdxRadioIndicatorPresence="{ keepMounted: true }" rdxRadioIndicator></span>
```

Use `{ keepMounted: true }` on the structural directive to retain the whole view while unchecked.
Style the settled unchecked state with `data-unchecked` when a retained indicator should be invisible.

## Accessibility

Adheres to the [Radio Group WAI-ARIA design pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radiobutton)
and uses composite roving tabindex to manage focus movement among radio items.

### Keyboard Interactions

| Key          | Description                                                                        |
|--------------|------------------------------------------------------------------------------------|
| `Tab` / `Shift` + `Tab` | Enters or leaves the group through its single tab stop. |
| `Space` | Requests selection when released on the focused radio. |
| `Enter` | Leaves selection unchanged. |
| `ArrowDown` | Focuses the next enabled radio and requests its selection. |
| `ArrowUp` | Focuses the previous enabled radio and requests its selection. |
| `ArrowRight` | Moves to the next enabled radio in LTR and the previous one in RTL. Requests selection. |
| `ArrowLeft` | Moves to the previous enabled radio in LTR and the next one in RTL. Requests selection. |

The checked item is the initial tab stop. Without a checked item, focus enters at the first enabled
item. After navigation, the tab stop follows the last focused item. Programmatic value changes and
declined requests leave that focus position in place.

Arrow navigation wraps and also supports `Shift`. `Home` and `End` retain their browser behavior.
Read-only groups allow focus to move without changing selection. A disabled group has no default
tab stop. A checked custom host with individual `aria-disabled` can retain its existing tab stop.
