# Menubar

#### A visually persistent menu common in desktop applications that provides quick access to a consistent set of commands.

Menubar coordinates a row of [Menu](?path=/docs/primitives-menu--docs) primitives. Each top-level
menu is a `rdxMenuRoot` with a standard `rdxMenuTrigger`; the menubar manages which one is open and wires
up Base UI-style Composite focus, arrow-key navigation, and hover-to-switch behavior between them.

<Canvas sourceState="hidden" of={Stories.Default} />

## Features

- ✅ Horizontal row of menus with a single open menu at a time.
- ✅ Open a menu by click or keyboard; once one is open, hovering a sibling trigger switches to it.
- ✅ ArrowLeft / ArrowRight move between triggers; ArrowDown / ArrowUp open the focused menu.
- ✅ Each menu reuses the full Menu primitive — items, checkbox/radio, submenus, separators.
- ✅ Escape closes the open menu and returns focus to its trigger.
- ✅ Headless — state is exposed via `data-popup-open` and menu item state attributes; styling is up to the consumer.

## Import

```typescript
import { RdxMenubarRoot } from '@radix-ng/primitives/menubar';
import { RdxMenuModule } from '@radix-ng/primitives/menu';
```

Or import the menubar parts through the module:

```typescript
import { RdxMenubarModule } from '@radix-ng/primitives/menubar';
```

## Anatomy

The structure follows Base UI's Menubar example. Each Menu Root owns a trigger and a Portal;
Positioner and Popup live inside that Portal. Submenus use the same structure inside their parent's
Popup. Angular's `ng-container` provides Root ownership, and `ng-template rdxMenuPortal` manages
mounting, exits and optional retention.

```html
<div rdxMenubarRoot>
  <ng-container rdxMenuRoot>
    <button rdxMenuTrigger>File</button>
    <ng-template rdxMenuPortal>
      <div align="start" sideOffset="4" rdxMenuPositioner>
        <div rdxMenuPopup>
          <div rdxMenuItem>New</div>
          <div rdxMenuItem>Open</div>
          <div rdxMenuItem>Save</div>
          <ng-container rdxMenuRoot>
            <div rdxMenuSubTrigger>Export</div>
            <ng-template rdxMenuPortal>
              <div side="inline-end" align="start" sideOffset="-4" alignOffset="-4" rdxMenuPositioner>
                <div rdxMenuPopup>
                  <div rdxMenuItem>PDF</div>
                  <div rdxMenuItem>PNG</div>
                  <div rdxMenuItem>SVG</div>
                </div>
              </div>
            </ng-template>
          </ng-container>
          <div rdxMenuSeparator></div>
          <div rdxMenuItem>Print</div>
        </div>
      </div>
    </ng-template>
  </ng-container>
  <ng-container rdxMenuRoot>
    <button rdxMenuTrigger>Edit</button>
    <ng-template rdxMenuPortal>
      <div align="start" sideOffset="4" rdxMenuPositioner>
        <div rdxMenuPopup>
          <div rdxMenuItem>Cut</div>
          <div rdxMenuItem>Copy</div>
          <div rdxMenuItem>Paste</div>
        </div>
      </div>
    </ng-template>
  </ng-container>
</div>
```

## Examples

### Default

The Base UI example structure: File with Export, Edit, View with Layout, and disabled Help.
The demo keeps the shared `demoMenubar` and `demoMenu` styles.
Click a trigger to open it, then hover the other triggers to switch, or use the arrow keys.

<Canvas of={Stories.Default} />

### Vertical

Use `<rdx-menubar-default orientation="vertical" />` to render the demo vertically.
Up/Down move between the closed triggers. The cross-axis arrow opens a menu: Right in LTR, Left in RTL.
Inside the popup, Up/Down navigate its items; Escape returns to the trigger.
The return arrow (Left in LTR, Right in RTL) closes the popup and returns focus to its trigger.

<Canvas of={Stories.Vertical} />

### Horizontal popup

The bar's `orientation` and each Menu Root's `orientation` are independent.
Use `<rdx-menubar-default menuOrientation="horizontal" />` for horizontal popup items, with
vertical submenus. Left/Right navigate the root popup in text direction. Down on Export opens its
submenu; returning with Left (LTR) or Right (RTL) can also navigate the containing lists.
Up returns a horizontal popup to its trigger. Each ancestor applies its own navigation axis.
The example keeps the same Portal → Positioner → Popup structure and shared demo styles.

<Canvas of={Stories.HorizontalPopup} />

### Keep mounted

Use `<rdx-menubar-default [keepMounted]="true" />` to retain both root and child Portal views.
Closed positioners hide those views and
remove their items from the Tab order; reopening reuses their DOM.

<Canvas of={Stories.KeepMounted} />

Removing the whole Menubar with `@if` destroys all owned menus and portals, including retained views
and unfinished exits, and releases background interaction and scroll locking. Removal emits no
extra close request or unfinished-exit completion. Use `finalFocus` on a Menu popup to return to a
surviving outside control when the bar's triggers are removed.

## Accessibility

### Keyboard Interactions

| Key               | Description                                                         |
| ----------------- | ------------------------------------------------------------------- |
| `ArrowDown`       | Opens the focused trigger's menu and moves focus to the first item. |
| `ArrowUp`         | Opens the focused trigger's menu and moves focus to the last item.  |
| `ArrowRight`      | Moves to the next trigger. Opens it if a menu was already open.     |
| `ArrowLeft`       | Moves to the previous trigger. Opens it if a menu was already open. |
| `Home`            | Moves to the first trigger.                                         |
| `End`             | Moves to the last trigger.                                          |
| `Escape`          | Closes the open menu and returns focus to its trigger.              |
| `Enter` / `Space` | Activates the focused item (handled by the Menu primitive).         |

Triggers move through the shared Composite focus model: only one trigger is in the tab order at a time.
The table describes a horizontal bar. With `orientation="vertical"`, Up/Down move between closed
triggers and Right (LTR) / Left (RTL) opens the focused menu. Popup item navigation remains vertical.
The opposite arrow returns focus to the trigger; preserved interaction mode reopens the same popup
without moving focus back inside. Escape closes the menu and ends that mode.
Horizontal trigger navigation follows text direction. Home/End always follow DOM order.
With menus closed, arrow keys move focus between triggers; with a menu open, sibling switching focuses
the new popup. Disabled triggers are skipped.

If the current menu becomes disabled while its popup owns focus, horizontal arrows can still switch
to an enabled sibling. Disabling a focused closed trigger keeps an enabled trigger in the Tab order.
With one enabled menu, the forward arrow preserves popup/item focus. The return arrow (Left in LTR,
Right in RTL) requests close/reopen and leaves focus on its trigger. With siblings, that same return
is followed by opening the previous menu through native focus.

Canceling the destination's opening keeps the current popup open. Canceling `sibling-open` keeps
that source menu open even though the destination has already opened, so two popups can remain.
Focus can move within the coordinator without bypassing cancellation through a focus-out close.
Escape closes the menu that owns the original key event; focus already on another trigger is preserved.
From a leaf in a nested submenu, the forward arrow switches to the next top-level menu.

For a canceled child close, Escape keeps focus in the child. A return-arrow close still moves focus
to the trigger and clears child highlight while leaving the child open. Closing state and navigation
focus are separate parts of this interaction. Navigation callbacks retain the original KeyboardEvent. Nested/vertical returns consume it before
the close request; horizontal bar navigation consumes it after the return request.
Keyboard submenu navigation follows Root ownership, so native hosts composed through `hostDirectives` do not
need to repeat the original popup, item or submenu-trigger selector attributes.

### Open state

Use `defaultOpen` on a child Menu Root for initial opening, or bind its `open` model to application
state. Without a native opening request, focus starts on Popup; ArrowDown then enters its items.
Native keyboard opening still selects the first/last item. External openings participate in sibling
coordination and return-focus behavior, just like interaction-driven changes.

## API Reference

### RdxMenubarRoot

The horizontal container. Provides the coordination context consumed by each `rdxMenuTrigger`.
Exposes `data-orientation`, `data-has-submenu-open`, and `role="menubar"`.

<ArgTypes of={RdxMenubarRoot} />

### Menu Trigger

Use the standard `rdxMenuTrigger` inside each top-level `rdxMenuRoot`. When it is a direct child
menu of `rdxMenubarRoot`, the menubar wires it for Composite focus, hover switching, and ArrowLeft /
ArrowRight navigation. There is no separate menubar trigger directive — the menu trigger reports its
interactions to the menubar through context, mirroring [Base UI](https://base-ui.com/react/components/menubar).

Sibling switching opens the new popup before closing the old one and moves focus into that popup.
Native trigger focus remains inside the bar during the transfer, so it does not cause a premature
focus-out close. The trigger reports `role="menuitem"`. The menubar's Composite root owns tabindex:
the current trigger uses `tabindex="0"` and the other triggers use `tabindex="-1"`, so Tab enters
the menubar on a trigger rather than focusing the container.

Native mouse-down opens with `trigger-press` before release; arrow opening reports `list-navigation`.
Sibling switching closes the old menu with `sibling-open`. Pointer switching reports `trigger-hover`
and then `trigger-focus` when the new trigger receives focus. These requests retain their original
native events. Whole-bar `disabled` is inherited by the child menus.

| Data attribute      | Present when                  |
| ------------------- | ----------------------------- |
| `[data-popup-open]` | This trigger's menu is open.  |
| `[data-pressed]`    | The trigger is pressed.       |
| `[data-disabled]`   | The trigger is disabled.      |

Style `[data-popup-open]` to keep the owning trigger marked while focus is inside its popup.
The demos apply the same muted background to open submenu triggers, keep a visible gap between
surfaces, and reuse the shared Menu colors, borders, shadows and item styles in every variant.

The menubar root exposes `data-orientation`, `data-modal` (when modal), and `data-has-submenu-open`
(present in open-on-focus interaction mode). Opening a directly owned menu enables this mode;
accepted `sibling-open` and `list-navigation` closes preserve it. Other accepted closes end the mode,
even when a canceled sibling close has left another popup open. Nested child closing does not end it.

### Menu parts

All other parts — `rdxMenuPositioner`, `rdxMenuPopup`, `rdxMenuItem`, `rdxMenuCheckboxItem`,
`rdxMenuRadioGroup`, `rdxMenuSubTrigger`, `rdxMenuSeparator`, … — come from the
[Menu](?path=/docs/primitives-menu--docs) primitive and behave identically here.
