# Select

#### A control that presents a list of options for the user to pick from, triggered by a button.

Select is headless — it ships no styles and exposes state via `data-*` attributes so you can style it
with any approach. Two positioning modes are available: **Popper** (Floating UI, anchored below the
trigger) and **Item-aligned** (the popup overlaps the trigger, aligned to the selected item, matching
native `<select>` behavior).

<Canvas sourceState="hidden" of={Stories.Default} />

## Features

- ✅ Controlled and uncontrolled value via `[(value)]`, with `defaultValue` / `defaultOpen` seeds.
- ✅ `readOnly` and `required` state, reflected on the trigger as `aria-readonly` / `aria-required`.
- ✅ Single and multiple selection with the `multiple` input.
- ✅ Angular forms integration through `ControlValueAccessor`: Reactive Forms, `formControlName`, and `ngModel`.
- ✅ Cancelable `onOpenChange` and `onValueChange` outputs with reason-aware `eventDetails`.
- ✅ Imperative `close()` / `unmount()` actions and per-close deferred unmount for external animations.
- ✅ Two positioning modes: Popper (Floating UI) and Item-aligned (native-like).
- ✅ Optional popup arrow with shared positioning and open/closed, side, alignment and uncentered states.
- ✅ Scroll buttons appear automatically when the list overflows the viewport.
- ✅ Typeahead: type a character to jump to matching items.
- ✅ Custom comparison (`isItemEqualToValue`), labels (`itemToStringLabel`), and native form serialization
  (`itemToStringValue`) for object values.
- ✅ Highlight-model navigation (`aria-activedescendant`) — focus stays on the listbox, not the items.
- ✅ Full keyboard navigation: ArrowDown / ArrowUp, Home, End, Enter / Space, Escape.
- ✅ Public interaction state via `openMethod`, `openInteractionType`, and `closeInteractionType`.
- ✅ `modal` (default) locks page scroll and makes outside content inert, with an optional `Backdrop`.
- ✅ Field integration on the trigger (invalid / disabled / required / focused state + `aria-describedby`).
- ✅ `rdxSelectLabel` automatically names and focuses the trigger; Root's `id` identifies the control.
- ✅ Native autofill, required validation and input access through `autoComplete`, `inputRef` and `nativeInput()`.
- ✅ WAI-ARIA `combobox` / `listbox` semantics with `aria-selected` and `aria-disabled`.
- ✅ Headless — state via `data-selected`, `data-highlighted`, `data-popup-open`, `data-placeholder`, `data-disabled`.

## Anatomy

### Popper positioning (Floating UI)

The popup is anchored to the trigger and positioned with Floating UI — the same approach used by
Dropdown Menu and Popover. Use `rdxSelectPositioner` to configure side, align, and
offsets.

```html
<ng-container rdxSelectRoot>
  <button rdxSelectTrigger>
    <span #v="rdxSelectedValue" rdxSelectValue placeholder="Pick one…">{{ v.slotText() }}</span>
    <!-- chevron icon -->
  </button>

  <div *rdxSelectPortal sideOffset="4" align="start" rdxSelectPositioner>
    <div rdxSelectPopup>
      <div rdxSelectArrow></div>
      <!-- optional scroll-up button -->
      <div rdxSelectScrollUpButton><!-- up icon --></div>

      <div rdxSelectList>
        <div rdxSelectGroupLabel>Group label</div>
        <div rdxSelectGroup>
          <div value="apple" rdxSelectItem>
            <span rdxSelectItemIndicator><!-- check icon --></span>
            <span rdxSelectItemText>Apple</span>
          </div>
        </div>
      </div>

      <!-- optional scroll-down button -->
      <div rdxSelectScrollDownButton><!-- down icon --></div>
    </div>
  </div>
</ng-container>
```

### Item-aligned positioning (native-like)

The popup overlaps the trigger, with the selected item aligned to the trigger's position — matching
the behavior of a native `<select>`. Use `rdxSelectItemAlignedPosition` and
`rdxSelectItemAlignedPositionContent` instead of the Popper wrappers.

```html
<ng-container rdxSelectRoot>
  <button rdxSelectTrigger>
    <span #v="rdxSelectedValue" rdxSelectValue>{{ v.slotText() }}</span>
  </button>

  <div *rdxSelectPortal rdxSelectItemAlignedPosition>
    <div rdxSelectPopup>
      <div rdxSelectItemAlignedPositionContent>
        <div rdxSelectList>
          <div value="apple" rdxSelectItem>
            <span rdxSelectItemIndicator><!-- check icon --></span>
            <span rdxSelectItemText>Apple</span>
          </div>
        </div>
      </div>
    </div>
  </div>
</ng-container>
```

### Change details and interaction state

`onOpenChange` and `onValueChange` expose `eventDetails.reason`, the originating DOM event, and a
`cancel()` hook. `RdxSelectRoot` also exposes `openMethod`, `openInteractionType`, and
`closeInteractionType`, so app logic can distinguish keyboard, mouse, and touch flows explicitly.

### Deferred unmount and imperative actions

Use `#select="rdxSelectRoot"` or a `viewChild(RdxSelectRoot)` query to call `close()` and `unmount()`.
`close()` requests a cancelable close with reason `imperative-action` and returns whether it was
accepted. Calling it while already closed does nothing. These methods adapt Base UI's `actionsRef`
capabilities to Angular template references and view queries; a React ref object is unnecessary.

In an accepted closing `onOpenChange` event, call `eventDetails.preventUnmountOnClose()` to retain
the popup for an external animation. The logical `open` state still becomes `false`, and the popup
has `data-closed` / `data-ending-style`. Its positioner is inert while closed, so retained options do
not keep accepting selections. Finish the animation, then call `unmount()` to complete the closing
phase and release the portal. The example runs a Web Animations API exit and completes closing
automatically; **Finish exit** skips to the animation's end.

The opt-out belongs to that accepted close. A canceled request or an opening request cannot retain a
later close. A late call is accepted only while the same close is pending. Reopening clears it; a
stale `unmount()` while open does nothing. Cancel an old application animation on reopening so its
callback cannot finish a different, later close. Repeated `unmount()` calls do not repeat
`onOpenChangeComplete(false)`. Calling `close(); unmount()` in one batch is also supported.

Normal closing still waits for Presence to finish its CSS exit. Manual completion bypasses another
exit wait, and `onOpenChangeComplete(false)` runs once after the close finishes. Focus returns to the
trigger unless the user deliberately moved focus elsewhere.

`<ng-template rdxSelectPortal [keepMounted]="true">` retains the view even after closing completes.
Here `unmount()` ends the closing phase; it does not destroy a keep-mounted view. The positioner hides
after closing completes and stops tracking its anchor. Reopening reuses the view and resolves the
current selected item. Changing `keepMounted` is independent of the per-close animation opt-out.
The shared lifecycle is documented in
[ADR 0026](https://github.com/radix-ng/primitives/blob/main/docs/adr/0026-popup-close-lifecycle-and-presence.md).

### Focus management

The popup owns DOM focus and uses `aria-activedescendant` for virtual navigation. Arrow keys and
typeahead update the highlight; Enter or Space commits a selection. The existing default keeps
Tab/Shift+Tab inside the open Select and does not close on focus-out.

Set `[closeOnFocusOut]="true"` on **Popup** to opt into the shared focus manager's focus-out policy.
Forward Tab moves to the next control after the trigger and closes with reason `focus-out`, without
committing the highlight. Shift+Tab requests closing back to the trigger. A canceled `onOpenChange`
request leaves the Select open. Moving focus to another control programmatically closes and preserves
that target; moving into a related child layer remains inside.

`finalFocus` accepts an element, `false`, or an interaction callback. It works with ordinary and
keep-mounted views. A closed retained popup no longer keeps its parent focus scope paused. Escape
closes the current layer and returns focus, while deliberate outside focus is preserved by default.

The opt-in preserves virtual navigation. Changing the default focus policy or moving DOM focus to
items still requires the real screen-reader review tracked in
[ADR 0027](https://github.com/radix-ng/primitives/blob/main/docs/adr/0027-select-focus-policy-and-retained-scopes.md).
Use this story's controls to compare both policies and the Dialog/Popover shells.

### Native forms and autofill

The native input serves browser behavior. Select's `ControlValueAccessor` and Signal Forms contract
connect its value to Angular independently of this bridge. Its visible button/popup anatomy needs a
native representation for browser autofill and constraints; direct DOM access does not give the button
those capabilities. When a primitive already has an input representing its form value, the shared
bridge can reuse that control. See
[ADR 0025](https://github.com/radix-ng/primitives/blob/main/docs/adr/0025-separate-angular-forms-from-browser-input-bridge.md).

Select creates a technical native input after hydration for submission, browser autofill and required
validation. Pass `autoComplete` such as `country` / `country-name`. Autofill matches serialized values
or value labels without case sensitivity, then rendered item text. Matching an object keeps its
original reference. Closed options may mount briefly in a hidden probe; the popup does not open or
take focus, and no open-change events are emitted.

The persistent input submits one scalar value. Multiple selections submit repeated entries through
separate hidden inputs, with a nameless input checking the required empty state. Browser autofill is
ignored in multiple, disabled and read-only modes. A canceled or unmatched autofill preserves the
committed value, dirty state and external form errors and restores the native input's value.
An enclosing Field supplies its name, disabled and required state; its name takes precedence over
Root's own `name` when both are provided.

Use `[inputRef]="captureInput"` with `(input: HTMLInputElement | null) => void`, or read
`select.nativeInput()` through `#select="rdxSelectRoot"`. The callback receives the element after
hydration, and `null` on callback replacement or destruction. The signal is `null` on the server,
before hydration and after destruction. Focusing a focusable technical input redirects focus to the
trigger; providing `inputRef` keeps an otherwise unnamed optional input focusable too.

Prefer `nativeInput()` for signal-based Angular access. The callback API adapts Base UI's `inputRef`
name without introducing a separate value store or requiring React-style ref objects.

`required` participates in browser constraint validation; it does not install an additional validation
engine or write Angular validation errors. Angular forms still own their validators and Field state.
Use `ngNativeValidate` on the form when opting into browser validation UI with Angular forms. Native
invalid events mark the control touched, so an Angular required validator can reveal a Field error.
While invalid, the technical input follows the visible trigger's bounds so the browser validation
message stays attached to the control through layout changes, scrolling and resizing.
The example includes an external-form multiple control, native submission and reset.

### Typed application wrapper

An application-owned component can extend `RdxSelectRoot<Value, Multiple>` and use
`provideRdxSelectRoot(YourSelect)` to rebind the primitive's context, floating-tree and form providers.
It inherits the inputs, cancellable events, CVA and Signal Forms contract; no second value store or
hand-written CVA is needed. Use `[multiple]="true"` or `[multiple]="false"` for precise mode inference.

The [wrapper source](https://github.com/radix-ng/primitives/blob/main/packages/primitives/select/stories/select-typed-control.ts)

### Base UI compatibility

The [versioned Select parity matrix](https://github.com/radix-ng/primitives/blob/main/packages/primitives/select/PARITY.md)
records the exact Base UI source commit, Angular adaptations, linked coverage and remaining gaps.
The Select contract now initializes an empty single selection to `null` and an empty multiple
selection to `[]`, compares values with `Object.is` by default, and exposes `items` and
`highlightItemOnHover`. The matrix tracks the remaining differences; this is not a claim of complete
behavioral parity.

### Labels and control ids

Place `rdxSelectLabel` inside Root to name the trigger automatically. It supports both a native
`<label>` and ordinary markup such as `<div>`. Clicking label text focuses the trigger without
opening the popup; nested interactive elements keep their own behavior.

Set `id` on Root to identify the trigger. Root forwards it without duplicating it on a separate
root element, and `rdxSelectLabel` derives its id as `<root-id>-label`. Customize the label id through
Root, not a separate `id` on Label. An explicit Trigger `id` overrides the forwarded control id;
removing an override restores its fallback. Container roots (`ng-container`) and Root/Trigger on
the same button are supported.

`rdxFieldLabel` remains the native label for a surrounding Field. The most recently registered live
label in a Field supplies its accessible name; removing it restores the preceding label. Explicit
`aria-labelledby` on Trigger takes precedence. Select.Label also reflects Field's validation and
interaction attributes.

<Canvas of={Stories.Labels} />

Label registration and interaction behavior live in `core`, shared by Field, Select and Combobox;
Autocomplete inherits the Combobox label through directive composition. The example retains the
existing Angular support for labeling an outside Combobox/Autocomplete input. Current upstream's
Combobox.Label targets a trigger; sharing this helper does not establish complete Combobox part parity.

### Labels before the popup opens

Pass `items` to Root as a record (`{ fr: 'France' }`), an array of `{ value, label }` descriptors, or
an array of groups with an `items` array. These provide text labels for `rdxSelectValue` before the
popup mounts and after it closes. They do not render the options; the template still owns the list.
The Angular label type is `string | number | null | undefined`; rich markup belongs in the template.

`itemToStringLabel` takes precedence for non-null values, followed by an object's explicit `label`.
Records match the value as a property key. Descriptor arrays match primitive values directly, or
an object's `value` property; they do not use the selection comparator to resolve arbitrary objects.
Use `itemToStringLabel` for objects such as `{ code, name }`.

A null option with a label in `items` overrides the placeholder. Numeric zero and empty text labels
are preserved. `[highlightItemOnHover]="false"` keeps keyboard highlighting independent of pointer
movement and pointer leave; clicking an item still selects it. The default is `true`.

<Canvas of={Stories.Items} />

### Migrating existing Select consumers

- A named empty single Select now contributes `name=""` to `FormData`, matching the persistent native
  input contract. Previously an empty value contributed no entry. Multiple empty selections still
  contribute no entries. Disabled controls are excluded.

- Root's `id` now identifies the trigger and is forwarded there. For a separate DOM id on a Root
  wrapper, use `[attr.id]` with a different value or put that wrapper outside Root.

- Empty uncontrolled values now start as `null` (single) or `[]` (multiple), replacing `undefined`.
  Angular bindings may still write `undefined`; use nullish checks for an empty single value.
- Selection now uses `Object.is` instead of structural equality. Keep object references stable or
  supply `[isItemEqualToValue]="'id'"` / an explicit comparator. To retain the previous deep comparison,
  import `isEqual` from `@radix-ng/primitives/core` and pass it as the comparator.
- Display labels no longer depend on mounted `rdxSelectItemText` nodes. Provide `items` or
  `itemToStringLabel` when item text differs from the raw value. Object `label` / `value` properties
  remain fallback labels.

## Accessibility

### Keyboard Interactions

| Key               | Description                                                                          |
| ----------------- | ------------------------------------------------------------------------------------ |
| `Enter` / `Space` | Opens the popup when the trigger is focused; selects the highlighted item when open. |
| `ArrowDown`       | Highlights the next item.                                                            |
| `ArrowUp`         | Highlights the previous item.                                                        |
| `Home`            | Highlights the first item.                                                           |
| `End`             | Highlights the last item.                                                            |
| `Escape`          | Closes the popup without changing the value.                                         |
| Character keys    | Typeahead — jumps to the first item whose text starts with the typed character.      |

Because interaction type is tracked explicitly (`openMethod`, `openInteractionType`,
`closeInteractionType`), consumers can branch on keyboard vs pointer/touch intent without guessing
from low-level DOM events. That matters for accessible UX: keyboard-only flows can preserve focus and
validation policy independently from touch and mouse dismiss/open behavior.

## API Reference

### RdxSelectRoot

The root context provider. Manages open state, selected value, dismiss/open lifecycle, and
interaction-type tracking. It implements Angular's `ControlValueAccessor` for Reactive and
template-driven forms while keeping `value = model()` for two-way binding and Signal Forms. Its
`onOpenChange` and `onValueChange` outputs are cancelable and include reason-aware `eventDetails`,
while `openMethod`, `openInteractionType`, and `closeInteractionType` expose how the popup was opened
or closed.

<ArgTypes of={RdxSelectRoot} />

| Action | Result | Behavior |
| --- | --- | --- |
| `close()` | `boolean` | Requests an `imperative-action` close through `onOpenChange`; returns `false` if canceled or already closed. |
| `unmount()` | `void` | Completes a pending closing phase; ignored while open or already complete. |

The methods are also described by the exported `RdxSelectRootActions` interface. `keepMounted` on
`rdxSelectPortal` determines whether the view remains after close completion.

### RdxSelectTrigger

The button that opens the popup. Must be a `<button>` element.

<ArgTypes of={RdxSelectTrigger} />

**Data attributes**

| Attribute          | Present when                                                            |
| ------------------ | ---------------------------------------------------------------------- |
| `data-popup-open`  | The popup is open.                                                     |
| `data-placeholder` | No value is selected (the placeholder is shown).                       |
| `data-filled`      | A value is selected.                                                   |
| `data-disabled`    | The select is disabled.                                                |
| `data-readonly`    | The select is read-only.                                               |
| `data-required`    | The select is required.                                                |
| `data-invalid`     | The control is in an invalid state (via `Field`).                     |
| `data-valid`       | The control is in a valid state.                                       |
| `data-touched`     | The select has lost focus after interaction.                           |
| `data-dirty`       | The selected value changed through user interaction.                  |
| `data-focused`     | The trigger is focused (via `Field`).                                 |

`aria-controls` points at the popup's id only while the popup is open; `aria-readonly` / `aria-required` / `aria-invalid` reflect the corresponding states.

### RdxSelectValue

Renders the current selection inside the trigger using Root's `items`, `itemToStringLabel`, or the
value fallback. Set a `placeholder` attribute for the empty state. `data-placeholder` reflects an
empty selection, including when a labeled null option supplies the displayed text.

<ArgTypes of={RdxSelectValue} />

### RdxSelectLabel

An accessible label associated with the trigger. Its id is derived from Root. A native `<label>`
receives `for`; other elements use `aria-labelledby` and focus the trigger when clicked.

<ArgTypes of={RdxSelectLabel} />

### RdxSelectItem

A single option in the list. Receives a `value` input and exposes `data-highlighted` (keyboard /
pointer focus) and `data-disabled`.

<ArgTypes of={RdxSelectItem} />

**Data attributes**

| Attribute          | Present when                                              |
| ------------------ | ------------------------------------------------------- |
| `data-selected`    | This item is selected.                                  |
| `data-highlighted` | This item is highlighted (keyboard or pointer).         |
| `data-disabled`    | This item is disabled.                                  |

The item also carries `role="option"`, `aria-selected`, and `aria-disabled`.

### RdxSelectPositioner

Wraps the popup panel when using Popper positioning. Accepts the same positioning inputs as
`rdxMenuPositioner` (`sideOffset`, `alignOffset`, `align`, `side`, `avoidCollisions`, …).

<ArgTypes of={RdxSelectPositioner} />

**Data attributes**

| Attribute            | Present when / value                                                       |
| -------------------- | ------------------------------------------------------------------------- |
| `data-side`          | Resolved side after collision handling — `top` / `right` / `bottom` / `left`. |
| `data-align`         | Resolved alignment — `start` / `center` / `end`.                          |
| `data-anchor-hidden` | The anchor is clipped/off-screen and the popup is hidden.                 |

**CSS variables**

| Variable                                   | Description                                            |
| ------------------------------------------ | ----------------------------------------------------- |
| `--anchor-width` / `--anchor-height`       | Size of the trigger (anchor), for matching the popup width. |
| `--available-width` / `--available-height` | Space available before the collision boundary.        |
| `--transform-origin`                       | Origin to scale/zoom the popup from, based on side/align. |

The deprecated `--radix-select-*` aliases of these variables are still emitted for one release.

### RdxSelectArrow

A decorative popup pointer, with `aria-hidden="true"`. `width` defaults to `10` and `height` to `5`.
Active item alignment keeps it hidden; the anchored touch/pinch-zoom fallback restores it.
The default SVG is created after hydration; the server renders the decorative host and its state attributes.

<ArgTypes of={RdxSelectArrow} />

| Input | Default | Description |
| --- | --- | --- |
| `width` | `10` | Width of the default SVG, in pixels. |
| `height` | `5` | Height of the default SVG, in pixels. |

| Attribute | Present when / value |
| --- | --- |
| `data-open` / `data-closed` | Reflects Root's open state, including an exit transition. |
| `data-side` | The resolved physical or logical side; `none` during item alignment. |
| `data-align` | The resolved `start`, `center` or `end` alignment. |
| `data-uncentered` | The arrow could not be centered on the trigger. |

### RdxSelectItemText

Marks the text node of an item so Select can read it for the trigger display and typeahead. No
inputs.

### RdxSelectItemIndicator

Visible only when the parent `rdxSelectItem` is selected. No inputs.

### RdxSelectGroupLabel

A non-interactive label for a group. No inputs.

### RdxSelectGroup

Groups a set of related items semantically. No inputs.

### RdxSelectScrollUpButton

Renders at the top of the popup and scrolls the list up when hovered. Appears automatically when

### RdxSelectScrollDownButton

Renders at the bottom of the popup and scrolls the list down when hovered. Appears automatically
when content overflows. No inputs.

### RdxSelectPopup
